# 模块 07：已采纳用例导出

本模块把已经人工采纳的用例变为可交付的 Excel 和 Markdown 文件。进入「项目 → 已采纳用例」，搜索或勾选「仅冒烟」，点击对应导出按钮。按钮旁的数量就是此次导出范围；不筛选时导出全部已采纳用例。

## 本轮边界

- 导出人工修改后的最终内容，保留需求、模块、功能点、优先级、类型、冒烟、步骤和预期结果。
- 保留用例 ID、生成记录 ID、Mock/AI 来源、人工编辑和依据变化标记，方便追溯。
- 每次 1–1000 条，按页面显示顺序导出。无匹配结果时禁用按钮；超过上限需缩小筛选范围。
- 已经采纳但依据发生变化的历史用例仍可导出，文件中明确标注「依据已变化」，使用前应核对。
- 导出不调用模型，不修改用例和评审，不新建业务表。只在内存中生成文件并返回浏览器，不在后端保存文件。
- 本轮不包含批量导入、导出模板自定义、任务队列、暂停和断点恢复。它们按后续模块展开。

## 请求如何走完

1. `ProjectTestcases.vue` 用同一个 `filtered` 计算结果展示卡片和提取用例 ID。导出期间锁定筛选和刷新，防止数量变化。
2. `api.ts` 把格式及 ID 列表 POST 给后端，不传递前端显示的用例正文。
3. `testcase_export.py` 重新读取项目已采纳用例，校验每个 ID。任何一条已删除、不属于该项目或未采纳，整个请求返回 409，不生成部分结果。
4. `export_xlsx` 或 `export_markdown` 使用当前人工版本、历史依据快照和来源标记生成文件。
5. 后端通过 `Content-Type` 标识格式，通过 `Content-Disposition` 的 UTF-8 文件名告诉浏览器如何命名，返回 `Cache-Control: no-store`。
6. 前端验证响应类型和非空正文，再将 Blob 转成临时 URL 并发起下载，随后释放 URL。成功提示代表已经发起下载，最终保存位置由浏览器决定。

接口：

```http
POST /api/projects/{project_id}/testcases/export
Content-Type: application/json

{"format":"xlsx","case_ids":["已采纳用例的 UUID"]}
```

`format` 取 `xlsx` 或 `markdown`。成功返回二进制文件正文，不是 JSON。422 表示格式、ID 或条数不符合约束；404 表示项目不存在；409 表示列表已过期或所选 ID 不在当前项目已采纳范围，需要刷新；400 表示单元格文本超出 Excel 上限，可改用 Markdown。

## 两种文件的处理

Excel 使用 `openpyxl`，包括 15 列、标题与导出数量、表头筛选、冻结窗格、自动换行和交替底色。步骤按序号及换行保存。所有字段强制写成文本，`=HYPERLINK(...)` 等用户输入不会被导出为公式。Excel 单元格最多保留 32767 个 UTF-16 单元，超限明确拒绝，不静默截断；视觉上放不下的长文本可从公式栏查看全文。

Markdown 使用 UTF-8，每条用例一个小节。标题和元数据转义 HTML、Markdown 特殊字符；步骤等正文放在文本代码块中，围栏长度根据正文动态增加，避免正文中的反引号提前结束代码块。

两种格式都把 XML/UTF-8 不可表示字符转换为可见的 `\uXXXX`，不静默删除。文件名清理路径分隔符和控制字符，保留中文项目名。

## 阅读顺序

1. `web/src/pages/ProjectTestcases.vue`：筛选结果、导出数量、下载状态和失败重试。
2. `web/src/api.ts`：共用错误处理、文件响应和 Blob 下载。
3. `backend/app/schemas.py`：`CaseExportInput` 格式、唯一 ID 和数量约束。
4. `backend/app/reviews.py`：`list_accepted` 如何选择人工版本及计算过期标记。
5. `backend/app/testcase_export.py`：范围校验、两种序列化、文件名和响应头。
6. `backend/tests/test_exports.py`：用真实解析器检查生成文件，而不只检查 HTTP 200。

## 升级与验收

从 `aitc-lite/` 运行：

```bash
source .venv/bin/activate
python -m pip install -r backend/requirements-dev.txt
```

本轮新增 `openpyxl==3.1.5`，安装后重启后端。已有数据、模型设置和 DeepSeek Key 保留。

- [ ] 采纳至少两条用例，其中一条人工编辑，一条为冒烟用例。
- [ ] 打开项目「已采纳用例」，不筛选时数量与列表一致，下载 Excel 后检查标题、步骤和人工编辑标记。
- [ ] 用搜索过滤到一条，导出 Markdown，确认文件只包含这一条以及最终修改内容。
- [ ] 清空搜索，勾选「仅冒烟」，导出结果只包含冒烟用例。
- [ ] 搜索无结果时，两种导出按钮均禁用。
- [ ] 检查文件中 Mock 示例、需求、功能点和生成记录 ID；真实模型结果应标记为 AI 生成。
- [ ] 修改来源需求后，已采纳用例仍可导出，文件明确显示依据已变化。
- [ ] 断开后端再导出，显示错误并保留筛选和列表；恢复后可以重试。
- [ ] 在另一个页面删除需求，再从旧用例列表导出，提示刷新，不能生成缺失一部分的文件。
