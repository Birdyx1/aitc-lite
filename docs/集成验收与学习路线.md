## 本轮结果

- 302 项后端测试通过，前端类型检查和生产构建通过，实际服务健康检查为 0.22.1。
- 新增一条跨模块自动烟测：项目 → 知识入库 / BM25 / 向量索引 / RRF / Mock 精排 → 功能点拆解确认 → RAG + 双专项后台生成 → 人工编辑/采纳/驳回 → Markdown 导出 → Judge → 人工执行记录/结束 → 两次独立评测/对比 → Agent 汇总 → 删除来源与重启核对。

- 浏览器逐个验证六个导航入口和相关读取 API 均为 200，助手切换保留。未调用用户真实模型，未消耗额度。

## 先跑自动验收

从 `aitc-lite/`：

```bash
source .venv/bin/activate
cd backend
python -m unittest discover -s tests -p test_acceptance_flow.py -v
```

看到一条集成测试 `OK`，说明临时环境中的主链路已贯通。这不是使用真实模型评判业务质量，也没有实际运行被测系统。

完整回归：

```bash
python -m unittest discover -s tests -v
```

另一个终端从 `aitc-lite/web/`：

```bash
npm run build
```

不需要新增依赖或迁移表。刷新开发页面即可使用项目导航；后端热更新或重启后健康接口显示 0.22.1。

## 手工验收按三轮走

### 第一轮：一条需求的生成闭环

1. 新建专门的「集成验收」项目，不用现有业务项目做删除练习。进入项目后，顶部导航始终指向这个项目。
2. 输入一条规则明确的小需求，例如：验证码有效期五分钟；正确且未过期允许登录，错误或过期时拒绝登录。补充实际系统已有约定，未确定的错误码或页面行为留待澄清。
3. 功能点页拆解后人工修改并确认纳入范围。检查没有虚构原文之外的接口、字段、角色或阈值。
4. 先选一个功能点生成完整草稿，检查功能/边界/异常和冒烟标签，再人工改一条、采纳一条、驳回一条。
5. 用「已采纳用例」核对人工修改版，导出 Markdown 或 Excel；文件应保留来源与依据状态。
6. 点击 Judge 评估当前草稿，核对理由、疑似幻觉及 Mock 标记。Judge 不是自动实测，不能代替人工确认。

真实生成和 Judge 分别可能计费。可沿用已经配置的模型做少量验证；先阅读各模块文档了解真实与 Mock 的差别。自动烟测不需要改动全局 Mock 开关。

### 第二轮：知识、可靠性与执行记录

1. 在相同项目知识库录入一段你能核对的规则，先做 BM25，再构建向量索引、测试语义和混合检索。核对来源、两路排名和精排状态，RRF/Rerank 分数不是业务正确率。
2. 生成时开启 RAG，并按需要选择接口/安全专项。核对引用对应实际知识，而非仅有 K1 标签；缺少事实应写待澄清。
3. 在有节点进度的生成任务上请求暂停，等待已暂停后恢复；核对没有产生第二份成功草稿。若实际调用太快来不及操作，可运行既有 `test_task_recovery.py` 的受控测试，不把快速成功误判为暂停故障。
4. 从已采纳用例创建一个人工执行任务。请在目标系统实际操作后记录结果；若只是学习界面，用环境/备注明确写「演示记录，未执行真实系统」。
5. 记录通过、失败或阻塞并查看历史；有未执行条目时不能结束，全部记录后可结束并锁定。通过率分母只包含通过和失败。
6. 打开项目助手查询概况，核对人工执行统计。保持助手打开，点击顶部「知识库」等入口，应切换页面且保留助手。

知识向量化、真实检索/精排可能调用已配置服务。来源删除、配置变化、重启等可靠性场景可优先使用自动测试，避免在你的正式数据上试错。

### 第三轮：MCP 和独立评测

1. 按 [模块 20](20-MCP客户端与项目工具授权.md) 运行本地 MCP 演示，先发现工具，再到项目「MCP 工具」授权。只读直接查询，写入/未知逐次确认；拒绝时不应执行。
2. 同名工具来自不同服务时应能区分；切换项目不能继承未绑定工具。外部数据范围仍取决于服务账号，而非项目 ID。
3. 在「离线评测」建立独立样本，先开启本次 Mock 跑完整与冒烟两次，查看共同样本、配置差异、匹配证据和分母。
4. 修改标准点后重跑，应排除内容变更的样本。词面召回只能作为代理指标，不是语义覆盖率。
5. 最后用少量真实样本验证生成与 Judge 内容。生成、Judge、Embedding/Rerank 成本分开观察，已知 Token 不等于完整账单；未知值不补零。

## 验收通过的标准

| 范围 | 应看到的结果 |
| --- | --- |
| 生成和评审 | 依据、人工修改与结论可追溯，失败不覆盖旧结果 |
| 知识增强 | 来源和降级明确，没有凭空引用 |
| 暂停恢复 | 已完成节点复用，未知调用结果需明确处理，不自动重放 |
| 执行管理 | 固定快照、人工结果和历史独立保存，结束锁定 |
| Agent / MCP | 项目工具范围受限、操作逐次确认、失败不自动重复副作用 |
| 独立评测 | 产物不进正式用例库，共同比较排除变更样本，分母可复核 |
| 页面与配置 | 同项目导航不串项目，配置 Key 不回显，离开未保存输入有提醒 |

一轮集成测试证明流程衔接，不证明所有真实服务已兼容或生成内容足够准确。遇到问题可提供模块、操作步骤、期望/实际结果和运行 ID；不要复制 Key。

代码入口：`backend/tests/test_acceptance_flow.py` 是可运行的主链路导读；`web/src/App.vue` 负责共用导航；`components/AgentDrawer.vue` 使用当前 Element Plus 的非遮挡侧栏选项。
