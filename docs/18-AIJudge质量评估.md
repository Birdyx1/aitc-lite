# 模块 18：AI Judge 质量评估

本模块增加独立的质量评估任务：读取一批草稿当前已保存的人工版本，检查相关性、可执行性、可验证性及疑似幻觉，保存可追溯报告。Judge 不改写草稿，不替代人工采纳/驳回，不重新生成用例。

## 使用与验收

1. 先生成一批用例草稿。可以是普通、专项或 RAG 生成。
2. 默认复用当前生成模型，无需复制 Key。若需要不同模型，进入侧栏「Judge 配置」，关闭复用开关，填写独立对话根地址、模型、Key 和超时后保存。
3. 「测试真实连接」只发送固定短消息验证对话连接，不评估项目内容；通过不代表评分质量。Mock 只验证流程。
4. 返回用例草稿，在「AI Judge 质量评估」点击「评估当前草稿」。未保存的编辑不参与评估，编辑对话框打开时不能提交。
5. 查看本次实际模型来源、Prompt/评分规则版本、三维分数及理由、疑似幻觉和建议。展开本地规则检查，比较确定性重复提示与模型意见。
6. 展开输入快照，确认标题、步骤、预期结果及人工版本号对应本次实际评估。知识引用与专项声明属于 AI 原稿，人工编辑后不会自动重新证明其有效。
7. 人工编辑后，旧报告应显示过期。再次主动评估会创建新记录，保留旧分数与旧输入。
8. Judge 失败时，草稿和旧成功报告仍可查看。点击失败记录的「重试评估」，确认可能重复计费后创建新记录；它会读取当前已保存版本与当前模型配置，而非覆盖旧失败记录。
9. 评估时离开或刷新，返回后查看持久任务。服务重启将未完成评估标为中断，不会自动重发可能已计费的请求。

真实评估会把所选批次的当前人工用例、生成时需求/功能点、知识与专项快照发送给实际选定模型。每次主动评估调用一次模型，最多评估该批次的 8 条用例，不额外检索知识或执行用例。

## 评分口径

每个维度是 0–5 的整数，不接受字符串、小数或布尔值：

| 维度 | 核对内容 |
| --- | --- |
| 相关性 | 是否针对指定需求、已确认功能点和适用专项 |
| 可执行性 | 前置条件和步骤是否明确、能操作 |
| 可验证性 | 预期结果是否可观察、可判定 |

评分锚点：0 无法评估或不满足；1 严重缺陷；2 明显不足；3 基本可用；4 良好；5 充分明确。每个分数必须给出理由。

当前固定门槛为「三项均 ≥3 且没有疑似幻觉标记」。门槛由服务端计算，模型不能自行填写或覆盖。平均分仅用于展示；不能用平均分掩盖某一项不足。疑似幻觉是待人工复核信号，没有标记也不等于已证明无幻觉。

页面显示成功评估数、达到门槛数和疑似幻觉用例数。失败没有有效报告，不伪装成 0 分或正常无问题。Mock 固定示例为三项各 3 分，其门槛统计不代表真实质量；如果被评草稿本身来自 Mock，也会明确标注。

版本：`case-judge-v1` / `judge-rubric-v1-threshold3`。

## 本地规则检查

本地检查不调用模型，结果作为输入快照的一部分保存：

- 忽略空白、大小写及全半角后标题重复。
- 前置条件、步骤和预期结果相同的疑似内容重复。
- 文本含“待澄清”的未确定条件。
- 需求、功能点或知识依据变化时的历史依据提示。

字段完整性与有效步骤继续复用已有结构校验；无效数据会明确报错，不静默丢弃。重复提示不自动删除用例，不改变 AI 分数，也不自动阻止人工决策。规则版本为 `case-rules-v1`。

## 模型配置

`GET/PUT /api/settings/judge`，`POST /api/settings/judge/test`。

默认没有本页配置记录时，直接解析当前生成模型；记录 `model_source=generation`。独立模式记录 `model_source=independent`，使用本页自己的 Key；服务失败不自动切换到生成模型或 Mock。

切换来源时保留独立字段，以便以后切回；读取不回显 Key。留空保留、填写替换、勾选清除。改变独立根地址必须替换或清除旧 Key。配置使用完整 PUT，调用方切换复用模式时也应保留原独立字段，或明确清除原 Key，而不是意外重置地址。

页面同时显示保存模式与实际模型；尚未配置生成模型时，默认复用模式也不能发起评估。连接测试使用当前已保存来源，修改后先保存。

## 评估接口与持久化

```text
GET  /api/projects/{pid}/requirements/{rid}/case-generations/{gid}/judge-runs
GET  /api/projects/{pid}/requirements/{rid}/case-generations/{gid}/judge-runs/{id}
POST /api/projects/{pid}/requirements/{rid}/case-generations/{gid}/judge-runs
```

提交体为 `{"request_id":"UUID", "retry_of":null}`，先写入数据库并返回 202，再由单进程工作协程执行。相同请求 ID 核实提交不重复调用；同一批草稿只允许一个活动评估。重试使用新请求 ID，并通过 `retry_of` 关联同批次已失败/中断的记录。

新增表：

| 表 | 内容 |
| --- | --- |
| `judge_settings` | 独立配置、复用开关及本机 Key |
| `judge_runs` | 输入与摘要、模型来源/公开配置快照、Prompt 全文/版本、评分规则、任务状态、报告、脱敏错误、耗时及重试关联 |

Key 不进入快照、报告、检查点或日志。模型配置校验摘要只用于比较，不返回前端。删除所属需求/项目或生成记录时，外键级联清理相关评估。

当前人工版本包括已保存编辑后的字段、评审版本和状态；不会自动使用编辑框尚未保存的文本。生成时的需求、功能点及知识引用仍保留历史快照，不能默默换成最新知识全文。

## 一致性与失败行为

- 排队期间草稿/依据、模型来源、配置或 Judge 规则变化：停止本次评估，未调用模型。
- 调用期间人工版本或依据变化：仍保存对原输入快照的完整报告，但读取时标记过期；重新评估才能对应当前版本。
- 评审状态改变也会使旧报告过期，即使正文没改；这是本模块按版本追溯的保守策略。
- 原生成依据已经过期时，允许评估历史记录，但明确提示不能当作当前需求/知识的验证结果。
- 结果必须完整且唯一地覆盖本次所有用例 UUID。漏项、重复、外部 ID、无效分数、缺少理由、非法文本、额外字段或输出超长均判失败，不部分采纳报告。
- 原始响应和异常不直接展示。评估响应上限 1 MiB，结构化文本上限 100000 字符，输入快照上限 512 KiB，超过输入上限不调用模型，不静默截断。
- HTTP 错误、超时、断连和服务重启不会自动重试。手动重试可能重复计费，但只重试 Judge，不重新生成用例。
- 模型执行中的任务不支持取消远端请求或节点暂停；重启后可创建新评估重试。原生成工作流的检查点与暂停恢复继续保留。

模型评分不是实测结果，不会将用例自动采纳、驳回、改写或标成执行通过。同一模型自评可能存在偏差，独立模型也仍需人工复核。当前不估算费用或补造 Token 使用量，耗时按本地实际执行记录。

## 学习顺序

1. `backend/app/judge_settings.py`：复用/独立解析与 Key 生命周期。
2. `backend/app/prompts/judge.md`、`judge_protocol.py`：评分标准、严格结果校验与统一门槛。
3. `backend/app/judge_runs.py`：本地检查、当前输入快照、持久队列、幂等与过期判断。
4. `backend/app/llm.py`：复用对话适配器，Judge 调用单独限制响应大小。
5. `web/src/pages/JudgeSettings.vue`、`components/JudgePanel.vue`：配置、报告、历史与重试。
6. `web/src/components/CaseReviewPanel.vue`：保存人工修改后通知刷新评分版本状态。
7. `backend/tests/test_judge.py`：协议边界、配置、队列、输入变化与失败重试验证。
