# 模块 11：BM25 关键词检索与命中展示

进入「项目 → 知识库」，在文档列表下方输入关键词或错误码，点击「检索知识」。例如先保存「验证码过期返回 E1001」，再检索 `E1001` 或「验证码过期」。

本模块对当前项目的有效知识分块做词法检索，展示排名、BM25 分数、命中词项、原文内容、文档版本、来源与分块位置，并可定位到来源中的命中块。

## 当前范围

- 分块正文检索，中文用 jieba 分词，英文标识和错误码保持完整。
- Top K 支持 1–20，页面提供 1/5/10/20；只返回有命中词项的正分结果。
- 同一项目独立计算词频、文档频率与平均块长度，其他项目的知识不会影响分数。
- 每次查询读取有效分块并临时建立 BM25，不持久化语料索引或缓存，因此更新和删除后下次查询使用新块。
- 不调用模型，不写入知识正文或模型配置，也不向用例生成注入内容。

向量、RRF、Rerank、RAG 引用继续按后续模块开发。词法检索不承诺理解同义改写；上方文档列表仍只按标题/来源文件名筛选，下方 BM25 只检索分块正文，二者独立。

结果是查询时的知识快照，外部页面修改文档不会主动推送。本页文档刷新、保存或删除会清空旧结果；打开来源时再次核对版本与块 ID，来源已变化则提示重新查询。

## 分词与输入

查询和正文采用同样的处理：

1. Unicode NFKC 规范化，再做 casefold。例如 `Ｅ１００１` 与 `e1001` 得到同一词项。
2. 保留 ASCII 英数标识，以及标识内部的下划线、连字符、点、斜杠和冒号，例如 `e1001`、`x-request-id`、`api/login`。
3. 中文片段使用 jieba 精确模式、关闭 HMM。词项展示在结果页，方便检查分词效果。
4. 标点和 Emoji 不作为词项；没有有效词项时给出明确提示。
5. 查询词项去重，重复输入 `E1001 E1001` 不放大分数；正文保留真实词频。不设额外停用词表。

查询最多 200 个字符、64 个不同词项。多词为相关度匹配，不是必须全部满足的布尔 AND：查询「验证码 E9999」时，也可能返回只包含「验证码」的块，结果会说明实际命中词项。`E1001` 不会按子串匹配 `E10010`。

## BM25 分数如何计算

本轮使用 `rank-bm25==0.2.2` 的 Okapi 词频与长度归一化实现，固定 `k1=1.5`、`b=0.75`，并在本项目子类中采用正值 IDF：

```text
idf(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))

score(q, d) = Σ idf(t) × tf(t,d) × (k1 + 1)
                       / [tf(t,d) + k1 × (1 - b + b × len(d)/avgdl)]
```

`N` 是本项目参与索引的分块数；`df` 是包含词项的块数；`tf` 是该块内词频；长度按分词后的词项数计算。更多词频有收益但逐渐饱和，长度归一化避免长块只凭篇幅得高分。

库默认 IDF 实现可能在小语料中产生零分或负分，本项目正值公式使单个块、某词出现在一半或全部块中的情况仍能得到正分。该差异已在算法版本 `bm25-okapi-positive-idf-v1` 中标明，不能把本项目分数误认为库默认输出。参考 [rank-bm25 源码](https://github.com/dorianbrown/rank_bm25/blob/master/rank_bm25.py)、[jieba 使用说明](https://github.com/fxsjy/jieba)。

分数只用于同一查询、同一语料的排序，不是概率或置信度，也不能直接与另一查询或将来的向量距离相加。相同分数按文档 ID、块序号及块 ID 排序，保证同一语料结果稳定。重叠块可能各自命中，本轮不做文档级合并。

## 语料有效性与错误处理

1. 数据库查询先限制项目，并只读取 `chunk.document_revision == document.revision` 的有效块。
2. 不含可检索词项的块不进入 BM25，避免空语料除零。
3. 排序期间使用脱离数据库会话的只读数据，不持有长读事务。
4. 返回前重新读取有效块 ID、文档版本和内容摘要，与原始语料摘要比较。若检索期间发现知识变化，返回 409 要求重新检索，不把旧内容当作当前结果返回。
5. 分词或评分故障返回 503，页面展示错误与重试，不伪装成“无命中”。

不同空结果分别说明原因：

| status | 含义 |
| --- | --- |
| `empty_corpus` | 当前项目没有有效分块 |
| `no_terms` | 查询中没有有效词项 |
| `no_indexable_chunks` | 有知识块，但正文没有可检索词项 |
| `no_matches` | 检索正常完成，没有正分命中 |
| `matched` | 有命中，可按排名查看 |

当前实现适用于本地小型知识库，耗时会随项目分块数量增长。将来增加缓存或持久索引时，需要保留版本失效和有效块核对，不能仅把这次临时索引搬进缓存。

## API 与返回内容

```http
POST /api/projects/{project_id}/knowledge-search
Content-Type: application/json

{"query":"验证码过期 E1001","top_k":5}
```

返回本项目 ID、原始查询、查询词项、算法/分词器版本、评分参数、语料摘要、有效/参与索引块数、总命中数、耗时、状态消息和 hits。

每条 hit 有 rank、score、matched_tokens、chunk_id、document_id、document_title、source_filename、document_revision、块位置及正文/摘要。Top K 只限制返回条数，`total_matches` 是本次全部正分匹配块数。

无效参数返回 422；项目不存在返回 404；词项过多返回 400；知识变化返回 409；分词/评分不可用返回 503。查询参数不接受任意项目 ID 覆盖路由中的项目范围。

## 代码导读

1. `backend/app/knowledge/bm25.py`：分词、正值 IDF、项目语料读取、评分与稳定排序。
2. `backend/app/knowledge_search.py`：输入、空结果、错误区分与返回前语料核对。
3. `backend/app/schemas.py` 的 `KnowledgeSearch*`：查询约束和可追溯输出。
4. `web/src/components/KnowledgeSearchPanel.vue`：查询、结果卡片、参数说明、旧请求失效。
5. `web/src/pages/ProjectKnowledge.vue`：文档变更清空结果、来源版本核对、命中块定位。
6. `backend/tests/test_bm25.py`：可复核公式、小语料与失效边界。

检索组件使用请求序号丢弃迟到响应；文档变化或输入改变后失效旧结果。服务错误保留查询，重试不会把旧结果误显示为本次命中。
