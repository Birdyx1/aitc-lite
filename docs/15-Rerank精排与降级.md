# 模块 15：Rerank 精排与降级

本模块增加独立 Rerank 配置、连接测试，以及项目混合检索的可选精排。使用路径是「BM25 + 向量 → RRF → 可选 Rerank → 最终 Top K」。生成时的 RAG 上下文注入仍在下一模块。

## 配置与验收

1. 进入侧栏「Rerank 配置」。如果使用硅基流动，可以点击「填入硅基流动示例」：根地址 `https://api.siliconflow.cn/v1`，模型 `BAAI/bge-reranker-v2-m3`。示例来自[官方文本 Rerank 接口文档](https://api-docs.siliconflow.cn/docs/api/rerank-post)，实际模型权限以你的账号为准。
2. 输入自己的 API Key，保存后点击「测试真实连接」。示例按钮不会填写 Key、保存或联网。生成、Embedding 和 Rerank 的配置独立，即使使用同一服务，也要在此明确填写 Key。
3. 测试会发送固定问题与两条固定候选文本，显示原候选编号的返回顺序和相关性分数。不会发送项目正文；真实测试可能计费。连接通过只证明协议可用，不能证明精排质量。
4. 进入「项目 → 知识库 → RRF 混合检索」。先保持「启用 Rerank 精排」关闭，查询并观察 RRF 结果。
5. 开启精排，用同一个问题再次检索。检查精排状态、模型和候选数，比较每条的「RRF 原名次 → 最终名次」，以及 Rerank 分数。名次可能保持不变，`applied` 状态、输入候选数和分数说明精排已参与。
6. 将最终返回设为 Top 1，精排候选保留 20。确认精排先处理 RRF 候选池，再截取最终结果，原 RRF 第 2 或更后面的分块有机会进入最终第一名。
7. 点击来源按钮，确认最终结果仍对应原文版本与高亮块。
8. 如需本地流程学习，可在配置页主动开启 Mock 并保存。此时使用字符重合演示排序，明确不代表语义精排能力。切换真实配置后再验收效果。

真实查询在向量可用时调用一次 Embedding；开启且配置精排、存在候选时，再调用一次 Rerank，把查询和入选分块正文发送给已配置精排服务。精排默认关闭，不会自动复制其他 Key、自动启用 Mock 或自动重试。

## 三种数量不要混淆

| 参数 | 含义 | 范围与默认值 |
| --- | --- | --- |
| `candidate_k` | BM25 和向量每路最多召回数 | 1–50，默认 20，不小于 Top K |
| `rerank_k` | 从 RRF 去重结果前部取多少条交给精排 | 1–50，默认 20；启用时不小于 Top K |
| `top_k` | 最终返回数 | 1–20，默认 5 |

RRF 候选并集最多 100 条，但本模块只精排 RRF 前 `rerank_k` 条。候选池以外的分块不会因精排被重新召回。成功后按精排分数降序排列，同分按原 RRF 名次排序；失败则返回原始 RRF Top K，而不是拼接部分精排结果。

## 接口与数据

```text
GET  /api/settings/rerank
PUT  /api/settings/rerank
POST /api/settings/rerank/test
POST /api/projects/{project_id}/hybrid-search
```

混合查询新增可选参数：

```json
{
  "query": "验证码过期怎么办",
  "candidate_k": 20,
  "rerank_k": 20,
  "top_k": 5,
  "use_rerank": true
}
```

不传 `use_rerank` 时默认 false，保持模块 14 的排序行为。响应新增 `rerank` 元数据：状态、原因、模型、Mock 标识、实际候选数和耗时。结果中 `rank` 为最终名次，`rrf_rank` 是原始 RRF 名次，`score` 继续表示 RRF 分数，`rerank_score` 为精排分数，未精排时为 null。

两类分数不会相加。精排分数允许任意有限数值，不强行限定为 0–1；不同模型分数也不代表相同置信度。

配置写入独立 `rerank_settings` 单行表，Key 存本机 SQLite，不在读取和错误响应中回显。Key 留空保留、填写替换、勾选清除；更换根地址必须替换或清除原 Key。已有生成和 Embedding 配置不改动。

## 协议与失败保护

后端向根地址追加 `/rerank`，发送 `model`、`query`、`documents`、`top_n=候选总数`、`return_documents=false`。仅支持文本索引/评分协议，不启用多模态或厂商专有参数。

要求 `results` 完整覆盖本次全部候选，每条有唯一的整数 `index` 和有限数值 `relevance_score`。不信任服务返回的文档正文，只通过输入索引映射当前项目分块。部分返回、重复/越界索引、布尔或字符串分数、NaN/Infinity、非法 JSON、超时、限流、错误状态及超过 1 MiB 的响应均视为失败。不开启自动重试、重定向或环境代理。

| 精排状态 | 行为 |
| --- | --- |
| `disabled` | 用户未开启；使用 RRF，不调用精排服务 |
| `empty` | 没有召回候选；不调用精排服务 |
| `unconfigured` | 已勾选但未保存配置；明确降级到 RRF |
| `applied` | 精排成功；显示新旧名次和分数，Mock 另行警示 |
| `fallback` | 调用或校验失败；完整保留 RRF 顺序与分数，显示原因，不自动重试 |

模块 14 的召回降级继续生效：例如向量索引过期时，可先使用当前 BM25 召回，再对这些候选精排；页面同时显示召回与精排状态。精排失败不会掩盖召回失败。两路召回都不可用仍返回 503。

在精排前后核对知识语料、Embedding 配置、向量索引和本次 Rerank 配置身份。期间变更返回 409，项目删除返回 404；不能把过期内容当作正常 RRF 回退。Key 和超时变化不改变模型身份，根地址/模型/Mock 模式变化会使本次查询失效。精排不改变向量空间，保存精排配置不要求重建向量索引。

## 学习顺序

1. `backend/app/reranking.py`：协议、完整索引校验和显式 Mock。
2. `backend/app/rerank_settings.py`、`schemas.py`：配置生命周期和固定连接探针。
3. `backend/app/hybrid_search.py`：RRF 候选窗口、精排前后版本检查和完整回退。
4. `web/src/pages/RerankSettings.vue`：配置、示例填入、未保存提醒与连接测试。
5. `web/src/components/HybridSearchPanel.vue`：主动开关、候选数和名次对照。
6. `backend/tests/test_rerank.py`：协议边界、独立配置和检索集成测试。
