# 模块 05：LangGraph 最小用例生成

状态：已实现，待用户验收。首次在 Lite 中实际引入 LangGraph。

## 本轮范围

每次选择一个已确认且纳入范围的功能点，生成一批用例草稿。支持完整策略（3–8 条）和快速冒烟（1–3 条），成功后自动保存，并可刷新和查看历史记录。

使用路径：项目 → 需求 → 用例草稿；也可从功能点页面点击“查看用例草稿”。未确认或已过期的功能点不能用于新生成，但已有历史草稿仍可查看。

这一轮尚未实现草稿编辑、采纳/驳回、正式用例库、导出、AI Judge、RAG、批量功能点生成、后台进度、暂停或断点恢复。拆开交付是为了先理解状态图和一次生成的事务边界。

## LangGraph 实际执行什么

```mermaid
flowchart LR
  START --> prepare[prepare：准备输入]
  prepare --> generate[generate：生成用例]
  generate --> validate[validate：结构与策略校验]
  validate --> END
```

实现位置：`backend/app/workflows/case_generation.py`。它通过 `StateGraph` 注册三个节点和边，`compile()` 后在 API 中 `await graph.ainvoke(...)` 执行。[官方 StateGraph 文档](https://reference.langchain.com/python/langgraph/graph/state/StateGraph)。

`CaseState` 是普通字典状态，包含需求快照、功能点快照、策略、来源、消息、原始响应、校验后的用例和实际经过的节点列表。节点返回要更新的字段，顺序流转。

- `prepare`：核对功能点与策略，构建系统提示词和业务输入。
- `generate`：真实模式调用既有 HTTPX 模型适配器；显式 Mock 模式返回示例 JSON。
- `validate`：解析 JSON、校验字段、步骤与策略，拒绝重复标题和无效场景组合。

数据库 Session、模型客户端和 API Key 不进入图状态。模型调用器通过运行时闭包注入，网络请求期间数据库事务已释放。图执行成功后，由 API 在数据库事务中保存记录和草稿。

当前 `compile()` **没有配置 checkpointer**。安装包包含 checkpoint 相关依赖，不表示本模块启用了持久化检查点。历史结果保存在业务 SQLite 中，不能用来恢复运行到一半的图。后续加入 checkpointer、任务状态与暂停/恢复。

LangGraph 会安装 `langchain-core` 等依赖，但目前实际模型调用仍是 `llm.py` 中的 HTTPX；未改成 LangChain 模型适配器，也不需要配置 LangSmith。

## 输入、输出和质量边界

输入包括已保存需求原文、单个已确认功能点的字段、生成策略。沿用用户已保存的模型配置，真实调用会发送这些内容；DeepSeek 官方域名继续显式关闭思考模式。每次一个功能点，输出预算 4096 Token，超时沿用模型设置。

用例包含标题、优先级、类型、冒烟标记、前置条件、步骤数组和预期结果。完整策略必须包含功能、边界、异常类型，且至少有一条正常主路径冒烟；快速冒烟仅包含 functional 且全部标记冒烟。

校验覆盖字段、长度、非空步骤、标题重复和上述结构要求，不判断业务结论是否正确。页面全部结果仍为待人工评审草稿，尚无采纳操作。未在需求中明确的数值、错误码和权限规则不能由 Prompt 鼓励虚构，实际结果仍需人工核对。

## 数据和输入变化保护

- `case_generations`：成功生成记录、请求 ID、请求指纹、原文哈希、清单 revision、功能点与原文快照、策略、来源、模型名称、Prompt 版本、节点轨迹与条数。
- `case_drafts`：该次生成下的用例，保存步骤 JSON 和其他结构化字段。

每次新生成独立保存，不覆盖旧草稿。功能点被编辑、移除或重新拆解后，历史记录依靠快照保留依据；不把草稿通过外键绑定到可删除的功能点行。删除需求或项目会级联删除相关生成记录和草稿。

调用模型前检查需求内容哈希、功能点清单版本、确认状态和纳入范围；模型返回后再取得写锁并重新检查。这防止等待模型时输入被修改后，旧结果仍写入当前需求。模型或结构校验失败不产生部分草稿。

## 重试语义

前端一次尝试使用固定 UUID `request_id`。如果保存已完成而响应丢失，“重试本次生成”会带原 ID 和原输入再次请求。后端发现同一成功记录后返回原草稿，不再次调用模型或重复保存。

同一 ID 携带不同输入返回 409。成功请求的重放返回原来的历史结果，即使当前功能点已经变化，也不会冒充一次新生成。用户改变功能点或策略，或成功后再点击生成，会创建新请求。

该机制防止重复保存，不承诺两个并发的未完成请求只调用一次模型：它们可能都调用模型，但最终只保存同一请求 ID 的一份结果。运行租约和更完整的任务状态在后续模块加入。失败请求没有成功结果可重放，用户主动重试会重新执行图。

本轮只保存成功历史，尚无失败任务列表。生成期间不提供页面内离开操作；浏览器强制刷新后，完成的结果可通过历史读取，未完成的图没有恢复入口。

## API 与阅读顺序

统一前缀：`/api/projects/{project_id}/requirements/{requirement_id}/case-generations`。

| 方法 | 后缀 | 行为 |
|---|---|---|
| POST | 无 | 执行图并保存成功结果，首次成功 201，成功重放 200 |
| GET | 无 | 当前需求下的成功生成历史 |
| GET | `/{generation_id}` | 读取该次草稿、输入快照及是否来自历史输入 |

推荐顺序：

1. `schemas.py` 的 `CaseFields`、`CaseGenerateInput`、`CaseGenerationOutput`。
2. `prompts/case_writer.md` 的输出格式和策略。
3. `workflows/case_generation.py` 的 State、三个节点与边。
4. `case_generations.py` 的前置检查、图执行、后置检查和保存事务。
5. `models.py` 的生成记录、草稿和快照。
6. `web/src/pages/CaseGeneration.vue` 的生成状态、请求 ID、重试和历史切换。
7. `tests/test_case_generations.py` 的幂等重放、模型等待期间修改输入、失败不入库等测试。

## 手工验收

- [ ] 在需求列表能进入“用例草稿”，未确认功能点时生成按钮禁用。
- [ ] 确认范围后，下拉框只显示已纳入范围的功能点。
- [ ] 完整策略生成 3–8 条，含正常、边界、异常；能看到步骤、预期结果和冒烟标记。
- [ ] 快速冒烟生成 1–3 条，全部为正常功能与冒烟。
- [ ] 成功后自动保存，刷新或重启后端后可从历史读取。
- [ ] 展开“生成依据与过程”，可核对原文/功能点快照、版本与步骤。
- [ ] 新生成不会覆盖旧记录，点击历史“查看”可切换。
- [ ] 真实模型出错时显示失败，原草稿保留，不自动切换 Mock。
- [ ] 显式 Mock 使用相同的图路径，结果明确显示 Mock。
- [ ] 原文或功能点改动后，旧草稿仍可查看且有历史输入提示；新生成要求重新确认范围。
- [ ] 返回需求和功能点页面，原有增删改与确认流程仍可使用。
