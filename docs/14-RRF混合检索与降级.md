# 模块 14：RRF 混合检索与降级

本模块在项目知识库中增加「RRF 混合检索」，合并 BM25 和向量候选，按分块 ID 去重，并展示每路排名、原始分数和融合贡献。单路检索入口继续保留，用于对比。尚不调用 Rerank 或生成答案。

## 手工验收

1. 打开「项目 → 知识库」，添加验证码、短信和退款等不同主题的规则。
2. 使用已保存的 Embedding 配置，在下方构建向量索引。
3. 在「RRF 混合检索」输入原文中的关键词或错误码，观察两路候选数、重合数和去重候选数。
4. 点击「查看来源与命中分块」，确认对应原文版本和高亮块。
5. 核对一条双路命中结果：两路贡献相加应等于 RRF 分数；没有被某路召回时，该路贡献为零。
6. 将「最终返回」设为 Top 1，保留每路召回 20 条；确认先融合候选池，再只返回最终第一条。
7. 换成与原文不同的问法，与下方单独 BM25、单独语义检索结果比较。使用真实模型验收语义质量。
8. 修改文档后，重新混合检索：向量路应显示索引过期并降级，BM25 返回新版本。重建后恢复双路召回。
9. 在没有向量索引的项目中检索，应明确提示仅使用 BM25。空项目返回空状态，不调用 Embedding。

查询时，若向量路可用，会向已配置服务发送一次查询文本，可能计费。不会自动构建索引、自动重试或自动切换 Mock。

## RRF 如何计算

采用等权 Reciprocal Rank Fusion，固定平滑常数 `k=60`，每路名次从 1 开始：

```text
RRF(chunk) = BM25 贡献 + 向量贡献
单路贡献 = 1 / (60 + 该路名次)
未被该路召回的贡献 = 0
```

例如某分块在 BM25 排第 1、向量排第 2，融合分数为 `1/61 + 1/62 ≈ 0.03252247`。BM25 原始分数与向量余弦相似度的量纲不同，所以不直接相加。RRF 只使用名次；融合分数不是置信度，也不能保证内容能回答问题。

实现依据 [Cormack、Clarke 与 Buettcher 的 RRF 论文](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)。本模块固定等权和 k=60，后续可结合离线评测调整，不引入额外参数学习。

每路默认最多召回 20 条，可选至 50 条，最终返回 1–20 条。每路召回条数必须不小于最终返回条数。按分块 ID 去重，重复正文但不同分块 ID 不合并；同分按分块 ID 稳定排序。向量候选由 Chroma 近邻检索提供，融合仅覆盖本次候选池，不等于遍历全库后的全局最优排名。

## 接口与流程

```http
POST /api/projects/{project_id}/hybrid-search
Content-Type: application/json

{"query":"验证码 E1001", "top_k":5, "candidate_k":20}
```

1. 读取当前项目有效分块和语料摘要、Embedding 向量空间摘要及已发布索引指针。
2. 释放读事务，基于同一分块快照执行 BM25 与向量召回。BM25 在本地线程评分；向量复用已有 Embedding 适配器与 Chroma 存储。
3. 返回前重新核对项目、语料、配置和索引指针。期间变化返回 409，项目删除返回 404，不把旧结果当作降级结果。
4. 按两路名次融合、去重并截取 Top K；来源正文从当前项目快照获取，不信任向量库中的外部来源。

响应包含 `routes` 两路状态、`degraded`、`mode`、每路候选数、候选并集数、交集数、查询词项和语料摘要。每条结果保留 `bm25_rank/score/contribution` 与 `vector_rank/score/contribution`，以及原有文档/分块追溯字段。

## 降级约定

| 情况 | 行为 |
| --- | --- |
| 两路都有候选 | 双路 RRF 融合 |
| BM25 无匹配或没有可分词词项 | 正常空召回，不标故障；可使用向量候选 |
| 未配置 Embedding、未建索引、索引过期 | 标记降级及具体原因，只用当前分块的 BM25；不调用 Embedding |
| Embedding 超时/限流/格式错误、维度不符或本地索引不可用 | 标记向量路失败，只使用 BM25；不返回第三方响应或凭据 |
| BM25 分词/评分失败 | 标记 BM25 路失败，可使用有效向量候选 |
| 一路失败、另一路正常但无候选 | 返回带降级原因的空结果；不能当作完整双路查询无命中 |
| 两路均不可用 | 返回 503，不伪装成正常无结果 |
| 空知识库 | 返回空状态，不调用模型 |
| 检索期间语料、配置或索引变化 | 返回 409，要求重新检索 |

Mock 配置始终明确标注，哈希向量只用于流程验证。文档刷新、编辑、删除及向量索引切换后，页面清空旧结果。外部变更在向量状态轮询或手动刷新时被页面发现；每次查询的后端版本检查不依赖轮询。仅浏览已返回结果不再次调用模型。

## 阅读顺序

1. `backend/app/knowledge/rrf.py`：纯融合函数与稳定排序。
2. `backend/app/hybrid_search.py`：输入校验、同快照召回、降级和版本检查。
3. `web/src/components/HybridSearchPanel.vue`：候选池、路状态、贡献表与来源事件。
4. `web/src/components/VectorSearchPanel.vue`：索引变化事件，让父页清除旧检索结果。
5. `backend/tests/test_hybrid_search.py`：算法与 API 集成测试，含真实本地 Chroma 和模拟 Embedding。
