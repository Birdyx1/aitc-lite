# 模块 06：人工评审与已采纳用例

状态：已实现，待用户验收。沿用模块 05 的 LangGraph 生成流程，本轮增加独立人工评审 API 和项目用例视图。

## 使用流程与范围

需求 → 用例草稿 → 编辑并保存人工修改（可选）→ 采纳或填写原因驳回 → 查看项目已采纳用例。

每条草稿支持标题、优先级、类型、冒烟标记、前置条件、步骤和预期结果编辑。步骤编辑区每行一个步骤，保存时忽略空行，限制 1–20 步。保存人工修改后仍为待评审，不等于采纳。

评审页可筛选全部、待评审、已采纳、已驳回；人工修改后可展开查看原始 AI 输出。项目列表和评审页均可进入“已采纳用例”，支持搜索标题/需求/模块/功能点及冒烟筛选。

本轮逐条评审，不含批量采纳、导出、已完成评审结论的撤销、已采纳用例再修订或版本历史。发现已完成结论需要修订时，先核对输入并重新生成新草稿；后续再设计正式修订流程。

## 状态与操作

| 当前状态 | 可进行的操作 |
|---|---|
| 待评审 | 编辑、采纳、驳回 |
| 已采纳 | 查看，进入项目已采纳用例视图 |
| 已驳回 | 查看驳回原因 |

编辑保持待评审。采纳和驳回是本轮的终态，不能互相切换或继续编辑。驳回必须提供非空原因。

草稿依据过期时仍可查看、编辑核对或驳回，但不能新采纳；需核对需求/功能点并重新生成。之前已采纳的结果不会自动丢失，项目用例视图显示“生成依据已变化”的提醒，保留当时内容供核对。

Mock 草稿也能用于练习评审，但项目用例视图持续标记 Mock 示例，不会改成真实 AI 来源。

## 数据结构与保存

新增 `case_reviews` 表，以 `draft_id` 为主键，同时是指向 `case_drafts.id` 的外键，一条草稿最多对应一条评审记录。保存评审 revision、状态、人工版本 JSON、是否曾编辑、驳回原因和更新时间。

- 原有 `case_drafts` 内容不被人工编辑覆盖，模块 05 的生成记录和请求重放仍返回原始输出。
- 评审 API 同时返回 `original` 和 `current`；有人工版本时展示人工版本，否则展示原稿。
- 没有评审记录的历史草稿默认返回待评审、revision=0，无需给旧数据批量补行。
- “已采纳用例”是筛选评审状态为 accepted 后的项目视图，不再复制一份用例，避免重复入库。
- 项目或需求删除时，草稿和评审记录通过外键级联删除。

每次编辑使用 `expected_revision` 检查版本。提交时先取得写锁，再读取最新评审状态和版本；过期编辑或未看到最新人工版本的采纳操作返回 409。界面保留当前输入，用户需核对后重新加载。

相同已完成采纳操作的重放直接返回既有结论；相同原因的驳回也可安全重放。重复请求不会新增第二条已采纳用例。不同结论或修改驳回原因会被锁定规则拒绝。

## 与 LangGraph 的边界

生成仍由 LangGraph 负责，人工评审通过独立 API 和 SQLite 状态管理完成。本模块没有给图增加 `interrupt` 或 checkpointer，人工评审等待期间没有运行中的图。

用户点击评审按钮不会调用模型，不消耗模型 Token。暂停、断点恢复和任务调度仍在后续模块。

## API 与代码导读

评审前缀：`/api/projects/{project_id}/requirements/{requirement_id}/case-generations/{generation_id}/reviews`。

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | 评审前缀 | 当前生成记录下的全部评审状态、原稿和人工版本 |
| PUT | 评审前缀 + `/{draft_id}` | `edit` / `accept` / `reject`，携带 expected_revision |
| GET | `/api/projects/{project_id}/testcases` | 当前项目已采纳的人工版本及来源 |

项目、需求、生成记录和草稿的关联范围逐层校验。不属于当前路径的资源返回 404，输入错误返回 422，版本/状态/依据冲突返回 409。

推荐阅读：

1. `models.py` 的 `CaseReview`，理解与原稿的一对一关系。
2. `schemas.py` 的 `CaseReviewInput`，理解不同动作的合法输入。
3. `reviews.py` 的 `review_output()` 与状态转换规则。
4. `reviews.py` 的 `list_accepted()`，理解只读项目用例视图。
5. `web/src/components/CaseReviewPanel.vue`，理解原稿/人工版本、表单和错误保留。
6. `web/src/pages/CaseGeneration.vue`，理解评审组件如何接入历史生成记录。
7. `web/src/pages/ProjectTestcases.vue`，理解用例筛选和来源提示。
8. `tests/test_reviews.py`，理解编辑冲突、重复采纳、终态保护和项目隔离测试。

## 升级与手工验收

无新增依赖。重启后端会创建新的评审表，原有生成记录和草稿保持原样，模型设置不变。

- [ ] 打开已有生成记录，旧草稿默认待评审。
- [ ] 编辑并保存标题、步骤和预期结果，保存后仍待评审；刷新后人工版本保留。
- [ ] 展开原稿对照，原始 AI 内容保持不变。
- [ ] 保存失败或版本冲突时，编辑弹窗保留输入；关闭未保存的编辑会提示。
- [ ] 采纳后卡片显示已采纳，编辑/采纳/驳回操作不再出现。
- [ ] 驳回必须填写原因；成功后显示已驳回及原因，不能再采纳。
- [ ] 状态筛选和数量随操作正确更新。
- [ ] 项目已采纳用例只展示 accepted 结果，展示人工修改后的内容。
- [ ] 搜索与仅冒烟筛选可用，Mock 来源有明确标记。
- [ ] 原文或功能点变化后，旧待评审草稿不能新采纳；已采纳结果保留且显示依据变化提醒。
- [ ] 切换项目不会看到其他项目的用例，删除测试需求会清理其评审记录。
