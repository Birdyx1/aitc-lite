# 模块 02：项目需求文本管理

状态：已实现，待用户验收。本模块不接 AI、不上传文件。

## 本次学习目标

在模块 01 的 CRUD 基础上，理解“一对多关系”和“页面路由”：一个项目包含多份需求，每份需求只能属于一个项目。页面路由决定当前项目，后端通过项目 ID 和需求 ID 共同约束操作范围。

主路径：项目列表 → 点击项目名或“需求” → 新建需求 → 填标题和正文 → 保存 → 查看原文 → 编辑或删除。

## 最小数据结构

`requirements` 表包含 `id`、`project_id`、`title`、`content`、`created_at`、`updated_at`。

- `project_id` 是指向 `projects.id` 的外键，并带索引。
- 标题 1–200 字，保存前去掉两端空白；正文 1–50000 字，拒绝纯空白，但保留有效正文的全部原始空白与换行。
- 列表只返回摘要，不加载长正文；点击查看或编辑时再读取详情。
- 需求新增、修改或删除时，同一事务内更新所属项目的更新时间。
- 删除项目会删除其需求；删除一份需求不会删除项目或其他需求。

SQLite 需要在每个连接上执行 `PRAGMA foreign_keys=ON`，仅写 `ForeignKey` 声明不会自动开启约束。`database.py` 中通过 SQLAlchemy 连接事件启用；数据库使用 `ON DELETE CASCADE` 处理级联，不需要在前端遍历需求删除。

本次只新增表，启动时 `create_all()` 可安全补建，已有项目保留。将来修改既有表字段时，需要显式数据库迁移，不能依赖 `create_all()` 自动改表。

## 代码导读

建议按以下顺序阅读：

1. `backend/app/models.py`：新增 `Requirement`，观察外键。
2. `backend/app/schemas.py`：输入校验、列表摘要、详情输出；`TimestampOutput` 复用时间序列化。
3. `backend/app/requirements.py`：项目范围内的五个 API；`require_requirement()` 同时检查两个 ID。
4. `backend/app/database.py` 与 `deps.py`：外键启用与每个请求的数据库 Session。
5. `web/src/router.ts`：`/` 为项目列表，`/projects/:projectId/requirements` 为项目需求页。
6. `web/src/api.ts`：需求输入、摘要、详情类型与请求方法。
7. `web/src/pages/ProjectRequirements.vue`：加载列表、详情读取、表单保存、删除确认、未保存提示。
8. `backend/tests/test_requirements.py`：如何验证跨项目隔离、原文保留与级联删除。

`App.vue` 负责侧栏、面包屑和 `<router-view>`。项目列表移到 `pages/ProjectList.vue`。页面之间没有共享可变业务状态，因此本模块暂不引入 Pinia。

## API

以下路径前缀统一为 `/api/projects/{project_id}/requirements`。

| 方法 | 后缀 | 行为 |
|---|---|---|
| GET | 无 | 当前项目的需求摘要列表 |
| POST | 无 | 创建需求，成功 201 |
| GET | `/{requirement_id}` | 获取包含正文的详情 |
| PUT | `/{requirement_id}` | 更新标题和完整正文 |
| DELETE | `/{requirement_id}` | 删除需求，成功 204 |

项目不存在，或需求不属于路径中的项目，均返回 404。输入不合法返回 422。项目隔离是数据范围校验，不是用户权限体系；本应用当前仍是本地单人版本。

正文通过 Vue 文本插值展示，不作为 HTML 执行，也不渲染 Markdown，因此 `<script>` 等内容仍是原文。后续文件导入或 Markdown 预览另行扩展。

## 手工验收

- [ ] 创建或选择项目 A，点击项目名或“需求”，进入需求空列表。
- [ ] 新建“登录需求”，正文含多行和缩进，保存后列表出现该需求。
- [ ] 标题或正文仅输入空白时无法保存；正文可保留非空文本前后的空格和换行。
- [ ] 点击“查看”，标题和正文与输入一致，原始换行和缩进保留。
- [ ] 编辑标题和正文，保存后查看详情，内容已更新。
- [ ] 搜索需求标题，无匹配时显示空搜索状态，清空后恢复。
- [ ] 刷新浏览器，地址仍是项目 A 的需求页，数据保留；重启后端后仍能读取。
- [ ] 编辑但不保存，关闭弹窗选择“继续编辑”，内容仍在；再选“放弃修改”，数据库内容不变。
- [ ] 编辑但不保存，使用浏览器后退，出现放弃修改提示；拒绝后仍在编辑页。弹窗关闭后可通过“返回项目列表”或侧栏返回。
- [ ] 项目 B 的需求页看不到 A 的需求。在 API 文档中用 B 的项目 ID 读取 A 的需求 ID，返回 404。
- [ ] 删除需求先取消，需求保留；确认后只删除该需求。
- [ ] 在专用测试项目下新建需求，删除该项目，确认框提示级联影响；确认后所属需求不残留，其他项目不受影响。
- [ ] 暂停后端，保存需求时弹窗显示错误、输入保留；恢复后端后核实列表，再保存。
- [ ] 原项目列表的新建、编辑、搜索和删除仍可使用。
