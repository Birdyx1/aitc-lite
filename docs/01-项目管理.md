## 目标与范围

先理解最小的前后端闭环：浏览器提交项目 → API 验证 → SQLite 保存 → 页面更新。此模块只做项目的创建、列表、详情接口、编辑、删除及页面搜索，不包含需求、模型调用、知识库或 Agent。

技术栈中的 Vue Router 和 Pinia 留到多页面或跨页面状态真正需要时引入。当前单页使用 Vue 的 `ref`、`reactive`、`computed`，状态直接在组件维护，避免为了学习一个 CRUD 先增加多层抽象。

建议先读 `models.py` 与 `schemas.py`，理解“保存什么”和“允许输入什么”；再读 `projects.py` 与 `database.py`；最后读 `api.ts` 和 `App.vue`，沿一次新建操作串起来。`main.py` 负责把后端各部分装配起来。

当前业务逻辑很少，API 直接调用数据库，没有额外的 service/repository 层。后续出现可复用业务或事务编排后再抽取。

## 一次新建请求

1. 点击“新建项目”，`openForm()` 初始化表单并打开弹窗。
2. 点击“创建项目”，`saveProject()` 先调用 Element Plus 表单校验。
3. `api.ts` 发出 `POST /api/projects`，开发代理转发到 `127.0.0.1:8001`。
4. FastAPI 使用 `ProjectInput` 校验：去两端空白、检查长度、拒绝额外字段。
5. `create_project()` 新建 SQLAlchemy 对象，通过 `session.commit()` 写入 SQLite。
6. API 返回 `201` 和 `ProjectOutput`，包含数据库生成的 ID 与 UTC 时间。
7. Vue 更新项目列表，关闭弹窗，显示成功提示。再次刷新则从数据库重新读取。

页面不把项目存入 localStorage。时间由数据库按 UTC 保存、API 显式返回时区，浏览器按用户本地时区显示。

## 接口

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/api/health` | 返回服务状态 |
| GET | `/api/projects` | 按更新时间、ID 倒序返回项目 |
| POST | `/api/projects` | 创建；成功 201 |
| GET | `/api/projects/{id}` | 读取单个项目 |
| PUT | `/api/projects/{id}` | 替换名称和描述 |
| DELETE | `/api/projects/{id}` | 删除；成功 204，无响应体 |

项目不存在返回 404，输入校验失败返回 422。页面搜索在完整项目列表中执行，本模块暂不引入分页；将来数据量增加后再改服务端搜索与分页。

## 手工验收

启动步骤见项目 README。下面的操作都在 Lite 页面完成。

- [ ] 第一次打开显示空状态，项目数为 0。
- [ ] 新建“商城测试”，描述“登录、订单和退款”；列表立即出现，项目数为 1。
- [ ] 名称输入纯空格无法保存；描述可以为空。
- [ ] 修改名称和描述，保存后列表立即更新。
- [ ] 搜索名称或描述关键词可以找到项目；无匹配时显示空搜索状态，清空恢复列表。
- [ ] 再建一个项目，确认项目数为 2，最近保存的项目排在前面。
- [ ] 刷新浏览器，两条项目仍存在。
- [ ] 停止后端并重新启动，再刷新页面，数据仍存在。
- [ ] 删除一个项目先点取消，项目仍在；再次删除并确认，项目数减 1。
- [ ] 停止后端后点刷新，页面显示连接错误；恢复后端并点“重新加载”，列表恢复。

验收完可以删除自行创建的测试项目。数据库文件不需要手工改动。
