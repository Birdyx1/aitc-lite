# 模块 22：离线评测与运行对比

入口：项目列表 → 离线评测。一个页面维护独立样本、创建批量运行并对比两次结果；运行详情展示每个样本的生成、Judge、匹配证据与快照。

离线指固定数据集评测，不是本地推理。真实生成、Judge、Embedding/Rerank 仍可能联网并计费；显式 Mock 运行不调用外部服务，适合先验收流程。

## 最小闭环

1. 新建评测样本：需求原文 + 人工定义的一项功能点 + 可选标准测试点。
2. 选择 1–20 个样本，固定策略、专项、RAG 与本次 Mock 模式，提交运行。
3. 后台逐样本复用同一个 LangGraph 用例生成图，再复用 Judge Prompt、解析器和固定门槛；不创建正式需求、草稿、评审或执行任务。
4. 分阶段保存生成、Judge、标准点匹配、重复提示、知识上下文、耗时及可获得的 Token。
5. 对比已结束运行：展示配置差异、样本差异，只用同一 ID 且内容哈希一致的样本计算共同指标。

生成失败不调用该样本 Judge，继续其他样本；Judge 失败保留生成用例和匹配结果。运行结束只表示批量队列处理完成，不表示样本全部成功或质量合格。

## 先用 Mock 验收

1. 确保生成模型配置已经保存，无需改动真实 Key。在项目「离线评测」点击「新建评测样本」。
2. 示例：名称「取消订单」、需求标题「订单取消规则」、正文「未支付订单可以取消，取消后显示已取消」；功能点「取消订单」，描述「验证取消操作与状态变化」。
3. 标准测试点每行一项，例如「取消订单」「状态为已取消」。标准点不会自动发送到生成提示词，防止答案泄漏；需求、功能点和验收标准仍作为合法生成输入。
4. 在「批量运行」新建运行，填写名称并开启「本次 Mock 演示」，选择样本后提交。这个开关只作用于本次评测，不修改全局生成或 Judge 设置。
5. 查看生成用例、固定 Mock Judge 分数、标准点匹配证据。Mock 模板可能只命中「取消订单」，不包含「状态为已取消」，这是可见的词面匹配结果，不应补成满分。
6. 再对相同样本发起一个「冒烟」Mock 运行。两次运行对比应显示 1 个共同样本，完整模板 3 条、冒烟模板 1 条；策略差异可展开。
7. 编辑样本的需求或标准点后创建新运行，与旧运行对比时该样本应归入内容变更并排除共同指标。只修改显示名称不会改变内容哈希。
8. 删除样本后，既有运行的输入、用例和指标证据仍保留；刷新只读状态，不重新调用模型。

Mock 固定分数、固定模板、词面命中率都不能证明真实模型质量。Mock RAG 只使用本地 BM25，不连接向量、Embedding 或 Rerank；页面和快照明确标注，精排实际不执行。

## 真实运行

关闭本次 Mock，并确保全局生成和有效 Judge 均关闭 Mock。Judge 默认复用生成模型，也可在既有 Judge 设置中配置独立服务。真实模式发现有效模型仍为 Mock 时明确拒绝，不静默切换。

先选择少量样本核对内容质量。每个成功生成的样本通常有一次生成与一次 Judge 请求；完整、冒烟、专项均复用已实现的生成约束。RAG 使用项目 BM25 / 向量 / RRF，可选 Rerank，额外请求与降级方式沿用既有检索服务。

不依赖正式业务需求或功能点确认表：样本中的功能点由用户在样本页人工定义，包含模块、名称、描述、验收标准、约束和优先级；运行固定该定义，不把样本导入正式需求。

RAG 查询由功能点名称、描述和需求标题拼接并限 200 字，最多注入 1–5 个分块，保存候选来源、排名、引用 ID、签名、精排和降级信息。无候选默认停止生成；明确允许无知识继续时保存空上下文与降级理由。即使严格模式因无候选失败，也保留已经取得的空检索快照。

## 指标口径

| 指标 | 分子 / 分母 |
| --- | --- |
| 生成成功率 | 产生有效用例的样本数 / 本次运行样本总数 |
| Judge 完成率 | 成功完成 Judge 的用例数 / 已成功生成的用例数 |
| Judge 样本完成率 | 完成 Judge 的样本数 / 成功生成的样本数（API 中同时保留） |
| Judge 可用率 | 达到固定门槛的用例数 / 完成 Judge 的用例数 |
| 词面场景召回 | 命中的人工标准点数 / 标准点总数 |
| 重复率 | 每个样本内被判为重复的后续用例数 / 已生成用例数 |
| 疑似幻觉 | Judge 有疑似幻觉说明的用例数量，需人工复核 |

所有比率同时返回分子、分母，分母为零时为 null，页面显示「—」。无标准点的样本排除召回分母；有标准点但生成失败的样本仍在召回分母，按未命中计，避免只评估成功样本而偏高。

### 词面匹配限制

方法 `literal-field-nfkc-v1`：文本先 NFKC 归一化、忽略空白和大小写，然后判断每个标准点整段是否包含于同一条用例的某个标题、前置条件、单步或预期字段中。不同字段不会拼接凑命中。

每个标准点只计一次，保存所有匹配用例 ID、字段和归一化文本片段。它是可复核的代理指标，不是语义覆盖率：标题提到某实体也可能匹配，改写或同义表述可能漏匹配，复杂业务约束需要人工核对或未来增加语义匹配器。标准点每项 2–500 字符，最多 20 项，归一化后不重复。

重复检查复用既有本地规则：标题相同，或完整前置条件、步骤和预期相同（忽略空白/大小写/全半角）。同一后续用例命中两类规则也只计一次，不跨样本混算，避免不同业务语境被误判重复。

Judge 复用 0–5 三维评分与固定门槛：每维至少 3 且没有疑似幻觉才计为可用。Judge 没完成的用例不进入可用率分母，同时必须查看完成率。Mock Judge 仍只是演示分数。

### Token 与耗时

记录生成与 Judge 响应返回的 prompt_tokens、completion_tokens、total_tokens；缺失或非法值记为未知，不补零或估算。不完整输出即使失败，只要服务已返回可解析 usage 也保留。HTTP 错误或未知请求结果可能没有 usage。

汇总的「已知生成/Judge Token」只累加有 total_tokens 的响应，并另列缺失次数，不代表完整账单。Embedding/Rerank 的 Token 未从现有适配器采集，不能将生成/Judge Token 当成整个 RAG 总消耗。Mock 没有外部 Token，固定展示未知并标注 Mock；费用统一为未知，不依据模型名推算价格。

检索、生成图、Judge 的阶段耗时使用本机实际墙钟计时，包含相应本地准备/保存开销；合计不含排队和停机时间，不等于提供商纯推理时间。

## 固定快照和可靠性

- 一个项目最多 200 个样本；单次运行最多 20 个，单次配置和样本快照最多 4 MiB。单次生成/Judge 输入最多 512 KiB，模型响应最多 1 MiB；共享用例解析器另有结构化文本上限。
- 样本保存和删除带版本校验，名称/需求/功能点/标准点输入有边界与 Unicode 校验。样本删除不删除历史运行，项目删除会级联清理全部评测数据。
- 提交使用稳定 run_id，相同请求幂等；同一项目只能有一个排队/运行/停止中的评测。后台协程串行处理，继续单进程部署。
- 提交时保存需求、功能点、标准点、样本版本和内容哈希，模型公开参数与配置签名、实际生成/Judge Prompt、Skill 完整版本与内容摘要、生成流程/指标规则/评测引擎版本，以及检索参数与知识库签名。Key 不进入快照或前端。
- 样本后续编辑不改变运行输入；模型、Judge、检索配置、流程或知识库变化会阻止后续调用，已有有效产物保留，并将运行中断。
- 「停止剩余样本」不会撤销已经发到服务商的请求；等待当前调用返回后保存可用产物，不开始新的模型阶段或样本。排队运行可直接停止。
- 页面按 1.5 秒只读轮询，可离开或刷新；服务停止或重启将未完成运行标为中断，不自动重放生成、Judge 或检索。没有评测 checkpoint/断点续跑，需主动创建新运行，可能重复计费。用例生成模块的暂停/恢复继续独立保留。

每个样本分别显示生成和 Judge 状态，成功用例先于 Judge 入库。失败时不覆盖其他样本，未完成的模型响应会提示结果未完整确认；不会把异常原文、服务端错误体或凭据写入展示。

## 两次运行对比

两次运行须结束或中断后才可比较。相同样本 ID 且内容哈希一致才算共同样本；同 ID 不同内容、仅左、仅右分别列出，排除共同指标。若无共同样本，比率显示「—」，不拿两个全量分母直接排名。

同时保留各运行全量指标、共同样本指标、共同样本逐项指标、生成策略/模型/Judge/Prompt/专项/检索配置差异及指标规则版本。指标规则或门槛不同会提示；Mock 与真实混比也需结合来源解释，不自动评冠军。检索实际上下文在样本明细，可进一步核对排名与降级。

## 代码阅读顺序

1. `backend/app/models.py`：EvaluationSample / EvaluationRun / EvaluationResult，独立于业务库表。
2. `backend/app/evaluation/schemas.py`、`api.py`：样本维护、快照、幂等、查询、停止和比较。
3. `backend/app/evaluation/runtime.py`：固定配置、工作队列、复用生成图/检索/Judge、阶段保存、重启保护。
4. `backend/app/evaluation/metrics.py`：词面匹配证据、重复去重、明确分子分母。
5. `backend/app/llm.py`：可选 usage 回调，仅向调用者提供合法 Token 数，不暴露原始响应。
6. `web/src/pages/Evaluations.vue`、`EvaluationRun.vue`、`components/EvaluationMetrics.vue`：操作、进度、明细和对比。
7. `backend/tests/test_evaluation.py`：隔离、协议、快照、失败、指标与运行生命周期。
