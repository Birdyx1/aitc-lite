# 模块 20：MCP 客户端与项目工具授权

AITC Lite 后端作为 MCP 客户端，项目 Agent 可以调用用户配置并授权的外部工具。入口是侧栏「MCP 服务」，项目助手里的「配置本项目 MCP 工具」负责项目绑定。基础生成、RAG、Judge 与生成任务暂停恢复继续可用。

## 最小闭环

1. 全局添加服务：stdio 指定绝对路径可执行文件与独立参数数组；Streamable HTTP 指定完整 MCP 端点。
2. 保存后「连接并发现工具」：官方 SDK 完成 initialize、tools/list 与分页，展示协商协议和输入 schema，不执行业务工具。
3. 进入项目助手 → 配置本项目 MCP 工具：逐项启用，人工选择只读、写入或未知，再保存授权。
4. 新提问时把已启用的工具 schema 加入原生工具列表；同名工具通过完整服务 ID 与工具名摘要形成不同的模型别名。
5. 只读工具直接调用；写入/未知工具展示服务、工具、说明、参数后等待用户确认。拒绝、超时或授权失效则不调用。
6. 参数摘要哈希、确认 token、确认时间、服务/工具、是否进入远端调用阶段与结果保存为审计；SSE 和断连只读轮询沿用项目助手。

服务的 readOnlyHint 等注解仅供参考，不能自动授予只读权限。外部数据范围由服务账号权限决定，项目绑定只限制工具可用性；若多个项目需要严格数据隔离，应配置受限账号或独立服务，不能只靠 Agent 的项目 ID。

## 升级与启动

版本 0.20.0。进入 `aitc-lite/`：

```bash
source .venv/bin/activate
python -m pip install -r backend/requirements-dev.txt
```

然后重启后端、刷新前端。新增服务、项目绑定、轮次工具上下文和外部调用四张表，无需迁移原表，既有数据保留。本版继续单进程运行。

官方 SDK 锁定 `mcp==1.12.4`，兼容当前 Pydantic 2.10.4；`sse-starlette==2.1.3` 保持现有 Starlette/FastAPI 版本，输入参数校验锁定 `jsonschema==4.26.0`。本地演示协商为协议 2025-06-18。参考 [官方 Python SDK 对应版本](https://github.com/modelcontextprotocol/python-sdk/tree/v1.12.4)、[MCP 传输规范](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)。

## 先用本地演示验收

仓库附 `backend/examples/mcp_demo.py`，仅用于学习传输和确认流程，不是平台业务的 MCP 服务端。`lookup_rule` 返回固定演示规则；`record_demo_note` 只写入该演示进程的内存，不写入真实项目。返回值明确带 Mock 来源。

### Streamable HTTP

在 `aitc-lite/` 新开终端：

```bash
source .venv/bin/activate
python backend/examples/mcp_demo.py --http --port 18021
```

在侧栏「MCP 服务」添加：

| 字段 | 示例 |
| --- | --- |
| 服务名称 | 本地 HTTP 演示 |
| 传输方式 | Streamable HTTP |
| MCP 端点 | `http://127.0.0.1:18021/mcp` |
| 凭据 | 留空 |
| 超时 | 20 秒 |
| 结果字符上限 | 12000 |

保存 → 连接并发现工具，应出现 `lookup_rule` 和 `record_demo_note`。

在任一项目助手配置 MCP：允许 `lookup_rule`，分类选择「我已审核：只读」；允许 `record_demo_note`，分类选择「写入（每次确认）」，保存。

在助手提问「使用本地 HTTP 演示的 lookup_rule 查询订单取消规则」，展开工具核对服务名和返回规则。再问「用 record_demo_note 保存一条演示便签，内容为模块 20 验收」，应先出现确认卡。核对后点「确认执行本次调用」，查看演示内存写入结果。另发一轮并拒绝，确认状态应显示 rejected，未发送远端。模型可能先查询内置工具，再决定是否调用 MCP；以实际工具卡为准。

等待确认期间刷新页面，仍能查看原待确认项；刷新不发送远端调用。每个确认最多等待 120 秒，且计入整轮 180 秒预算，先到为准。终端按 Ctrl+C 停止演示服务。

真实 Agent 仍调用已保存生成模型，可能计费。本地演示服务本身不收费；要完整测试模型选择 MCP 工具，生成模型需使用真实模式并支持原生 Tool Calls。显式 Agent Mock 只演示本地内置查询，不提供或调用 MCP 工具，避免 Mock 意外触发外部操作。

### stdio

无需另起演示服务终端，客户端每次操作会启动并清理子进程。在 MCP 服务页选择 stdio：

- 可执行文件：本项目 `.venv/bin/python` 的绝对路径，本机是 `/Users/xueganping/StudyProject/quality/AITC-20260811/aitc-lite/.venv/bin/python`。
- 参数 JSON 数组：`["/Users/xueganping/StudyProject/quality/AITC-20260811/aitc-lite/backend/examples/mcp_demo.py"]`。
- 环境变量凭据留空，保存并发现工具，再按项目授权。

无需 Shell 拼接，参数中的空格作为单个参数保留。stdio 每次操作独立进程，演示内存便签不会跨调用保留；需要持久状态的实际服务应使用其自己的存储。客户端退出会关闭 stdin、等待或终止进程树，stderr 不转发至应用日志。

## 配置与授权规则

- 服务最多 30 个，发现最多 50 个工具、最多 10 页；每个项目最多启用 24 个外部工具。新工具默认关闭、分类默认未知。
- 服务每次保存清空目录并增加版本；成功重新发现目录也增加版本。已有项目授权失效，需重新选择并保存，旧轮次不能沿用旧权限。
- HTTP 仅支持 Streamable HTTP，端点不接受用户名/密码、query 或片段。凭据支持 Authorization、X-API-Key、API-Key 三种头；不支持 OAuth 登录、Cookie 或任意自定义头，也不兼容所有外部服务鉴权。
- stdio 必须填写绝对可执行文件路径，只继承固定基础 PATH 和显式配置变量；SDK 默认继承的其他变量被覆盖为空。不自动继承模型 Key、代理或父进程凭据。服务若确实需要 HOME 等变量，应显式填写。
- 凭据留空保留，新字典完整替换，勾选清除可移除。改变目标、命令或参数时必须同时替换或清除凭据。凭据保存在本机 SQLite，接口只返回名称；已知 Key/token 在工具结果和对话中遮蔽。不要将凭据放在名称、命令、参数或 URL 中。
- 服务配置只能由用户在设置页维护，Agent 没有修改配置或启动任意新命令的工具。stdio 是本机程序执行能力，应使用你信任的服务。
- 输入 schema 必须为 object；本版拒绝 `$ref` / `$dynamicRef`，不远程加载 schema。单 schema 最多 32000 JSON 字符，目录最多 256000 JSON 字符。参数先按保存的 schema 校验，不通过则不发远端。

服务描述、工具输出都作为外部数据，不能改变系统规则或授予新权限。结果默认只用于当前对话，不自动写入知识库。

## 调用可靠性与边界

```text
新提问 → 固定项目工具目录和授权版本 → 原生 function tools
  → 校验参数与当前授权
  → 只读：直接调用
  → 写入/未知：持久待确认记录 → 展示原参数 → 确认 token + 参数哈希
  → 再核对授权与配置 → 先记调用阶段 → 官方 SDK tools/call
  → 保存成功、失败或结果待核实 → 返回模型整理答复
```

确认接口只记录决定，不能直接发远端请求；重复确认幂等，参数或服务、目录、绑定、模型配置变化会拒绝旧确认。同一轮中相同服务、工具和参数的写入/未知调用若已进入远端调用阶段，后续重复请求会被阻止。

远端报错、超时或连接中断后，可能无法判断是否产生副作用，工具标记 unknown（结果待核实）；服务重启时标记 interrupted，并保留是否进入远端阶段。该阶段标记不是外部成功的证明，连接初始化也可能失败。不得直接重新发送写入，先到外部系统核实；应用不自动重试或恢复外部写入。

未发送的待确认项在拒绝、超时、服务删除、权限撤销或重启后失效。关闭侧栏不取消后台任务；服务启动后不会自动重放排队、运行或待确认的 Agent 轮次。Agent 没有新增 checkpointer；用例生成的暂停/断点恢复独立保留。

每轮仍最多 4 次模型调用、6 次工具调用。MCP 连接加调用使用服务配置的 5–40 秒超时，确认等待另计，但总计不超过整轮 180 秒。后台 Agent 串行处理，等待确认期间其他轮次排队。

MCP 文本/结构化结果超过配置字符数时返回带截断标记的预览；Agent 整体结果仍受 12000 字符上限限制。图片、音频和资源只显示类型提示，不自动加载。这是解码后显示长度限制，不是 SDK 传输层的硬内存配额；本版面向受信任、本地单人服务。Resources、Prompts、Sampling、Elicitation、旧 HTTP+SSE 及自动重新发现不在本模块范围。

连接失败不会关闭内置工具；模型可以继续查询项目。但外部结果失败时不能声称操作成功。真实模型的选择与答复仍需人工核对。

## 学习代码顺序

1. `app/models.py`：服务、绑定、轮次目录和外部调用记录。
2. `app/mcp/client.py`：官方 SDK 生命周期、stdio/HTTP 会话、发现与调用。
3. `app/mcp/registry.py`：schema 校验、命名空间、项目工具列表与版本保护。
4. `app/mcp_settings.py`：配置、发现、项目绑定与凭据处理。
5. `app/mcp/runtime.py`：待确认、再次核权、调用阶段标记与重复保护。
6. `app/agent_sessions.py`：提交目录快照、工具分发、确认 API 和审计输出。
7. `web/src/pages/McpSettings.vue`、`ProjectMcp.vue`、`components/AgentDrawer.vue`：配置、授权和逐次确认。
8. `backend/tests/test_mcp.py`：官方传输与权限/确认边界。
