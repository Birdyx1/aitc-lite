# 模块 09：节点检查点、暂停与恢复

本模块让后台生成任务可以在节点之间暂停，随后复用已保存结果继续执行。进入「项目 → 需求 → 用例草稿」，在生成任务中点击「暂停」，任务停下后点击「恢复任务」。

## 暂停如何生效

- 排队中：立即变为已暂停，不调用模型。
- 运行中：记录暂停请求，等待当前节点执行完成并把结果保存到检查点，再停止后续节点。
- 模型正在生成：等待这次请求返回，不强行取消。模型结果保存后暂停，恢复时继续校验，不再重复调用该次模型。
- 校验完成、尚未保存草稿：可保留完整校验结果，恢复后只做版本核对和入库。
- 如果保存事务已经先完成，暂停返回当前任务不能暂停，刷新后可看到完成结果。

页面同时显示「已完成节点」和「检查点已保存」，两者在进度落库的短暂间隙可能不同。暂停后没有工作协程继续执行这条任务，其他需求的排队任务仍可执行。

Mock 运行很快，可能来不及点击暂停就已完成。可以用真实模型运行观察，开发验证采用可控延迟的本地模拟服务，无需真实模型费用。

## 恢复的边界

恢复沿用原任务 ID 和生成记录 ID，重新检查当前需求、功能点确认版本、输入哈希、模型配置和流程版本。同一需求有其他排队/运行任务时，需先等待其结束。

1. 已保存的模型输出和校验结果直接复用，不重做对应节点。
2. 部分节点输出可能已经保存为 pending writes，但完整快照还未合并；恢复会继续合并并推进，也不会重复该模型调用。
3. 服务重启仍不自动恢复。运行中的任务标为已中断，用户手动恢复；已暂停任务继续保持暂停。
4. 模型调用途中服务停止、没有留下可复用结果时，无法判断外部服务是否已经执行和计费。页面显示「确认后恢复」，只有用户确认允许重新调用才提交恢复请求。
5. 同一个任务重复或并发恢复只会重新排队一次；完整草稿继续依靠同 ID 重放和事务整批保存避免重复入库。
6. 模块 08 及以前没有控制记录的历史中断任务不补造检查点，页面说明无法恢复，需重新生成。已有成功草稿仍可查看、评审和导出。

失败任务也可在检查满足时恢复。如果模型输出本身不符合校验，恢复会复用这份输出并再次报错；应重新生成以请求新的模型结果。更改模型配置、需求或功能点后，旧任务不能直接恢复，需要恢复原配置或重新生成。流程文件/提示词版本变化时也需重新生成。

“断点恢复”保证复用已经持久化的结果；外部模型调用尚未保存结果时，不能承诺外部服务恰好执行一次。

## LangGraph 与存储

使用 LangGraph 的 `checkpointer`、固定 `thread_id` 和 `durability="sync"`。每次推进一个节点，完成持久化后再检查是否暂停；恢复时使用同一个 thread_id，并以 `None` 继续原图。相关机制见 [LangGraph 检查点说明](https://docs.langchain.com/oss/python/langgraph/checkpointers)。

`TaskCheckpointSaver` 是本项目实现的 SQLAlchemy 检查点适配器，继承 LangGraph 的 `BaseCheckpointSaver`，不是新增的外部服务。它把完整检查点、父检查点、元数据和节点 pending writes 存在 Lite 原有 SQLite 数据库中。同步/异步读写接口共享同一套存储逻辑，异步接口通过线程执行短数据库操作。

本适配器只用于当前三个节点的 JSON 字典状态，不是通用的所有 LangGraph 类型适配器。不加载 pickle 或任意对象；异常写入使用固定标记，避免把异常对象或第三方原始错误体存入检查点。

API Key 保留在现有模型配置中，执行时通过闭包注入，不进入图状态。模型返回的同值 Key 在进入检查点前由现有模型适配器隐藏。检查点包含需求原文、功能点、提示词和模型输出等业务内容，保存在本地数据库，随项目/需求删除级联清理。

新增三张表，无需修改已有表：

| 表 | 保存内容 |
| --- | --- |
| `generation_task_controls` | 暂停请求、流程版本、模型调用结果尚未确认的标记 |
| `graph_checkpoints` | 图快照、父检查点、元数据 |
| `graph_checkpoint_writes` | 各节点已持久化但可能尚未合并的输出 |

本轮继续采用单进程、单工作协程的本地队列。多进程租约、分布式恢复和外部工具副作用恢复不在本模块范围，MCP 接入后单独处理。

## API

共同前缀：`/api/projects/{project_id}/requirements/{requirement_id}/generation-tasks`。

```http
POST /{task_id}/pause
```

返回 200 代表暂停请求已记录，返回的 status 可能仍是 running，需继续查询直到 paused。

```http
POST /{task_id}/resume
Content-Type: application/json

{"retry_uncertain_model_call":false}
```

正常恢复使用 false。没有可复用模型结果且上次模型调用可能已发生时，false 返回 409；用户明确确认后使用 true。恢复接口不接受新需求、新模型或新的任务 ID。

任务输出新增 `pause_requested`、`can_resume`、`requires_model_retry`、`checkpoint_nodes` 和 `resume_block_reason`。任务列表不会返回原始检查点、模型原始文本或控制摘要。

## 代码阅读顺序

1. `backend/app/workflows/case_generation.py`：图仍为 prepare → generate → validate，编译时接受 checkpointer，流程摘要用于阻止不兼容恢复。
2. `backend/app/checkpoints.py`：完整快照、pending writes、JSON 存储和异步适配。
3. `backend/app/case_generations.py`：按节点推进、读取检查点、恢复及保存前再次核对暂停请求。
4. `backend/app/generation_tasks.py`：暂停/恢复接口、重试确认、控制记录和任务状态。
5. `backend/app/models.py`：三张新表的外键与级联删除。
6. `web/src/pages/CaseGeneration.vue`：边界暂停提示、恢复确认、控制请求与轮询之间的状态保护。
7. `backend/tests/test_task_recovery.py`：恢复后模型调用次数、崩溃窗口、并发和数据清理。

## 升级

从 `aitc-lite/` 执行：

```bash
source .venv/bin/activate
python -m pip install -r backend/requirements-dev.txt
```

显式锁定已有的 `langgraph-checkpoint==4.3.0` 接口版本，无需新增外部服务。后端重启自动创建新表。前后端版本为 0.9.0。原有模型设置、项目和用例保留。

## 手工验收

- [ ] 提交一个耗时较长的生成任务，运行中点击暂停，页面先显示等待当前节点结束。
- [ ] 等到已暂停，检查点显示准备输入和生成用例，尚未出现新草稿。
- [ ] 刷新页面，任务仍暂停；点击恢复后继续校验和入库，任务 ID 保持不变。
- [ ] 暂停后重启后端，任务仍可恢复；成功结果只出现一批。
- [ ] 生成途中停止后端再重启，任务中断；若模型结果未保存，恢复需确认可能重新调用，取消不会发送恢复请求。
- [ ] 同时打开两个标签页恢复同一任务，不会重复生成草稿。
- [ ] 排队任务可立即暂停，不阻塞其他需求任务。
- [ ] 暂停后修改需求或模型配置，页面说明不能恢复；重新生成使用新的任务。
- [ ] 历史无检查点任务显示限制，历史成功草稿仍可评审和导出。

## 开发验证

2026-10-26：75 项后端测试通过（63 项回归、本模块 12 项），覆盖运行/排队暂停、暂停后跨服务重启恢复、模型调用中断确认、已完成输出复用、pending writes 崩溃窗口、校验完成后只入库、并发恢复、需求/配置/流程变化、跨项目访问、级联清理、旧任务限制及凭据隐藏。前端类型检查和生产构建通过，共用依赖体积提示保留。

浏览器使用临时数据库与延迟模拟模型，验证等待暂停、刷新后暂停保留、恢复成功、失败后重新调用确认、取消不发送恢复请求，以及确认后恢复成功。未调用真实 DeepSeek，也未改动用户业务数据或模型配置。

## 学习问题

1. 为什么暂停模型调用时不能立即显示“已经暂停”？
2. 为什么只记录完成节点名称不足以恢复？
3. 完整 checkpoint 与 pending writes 分别覆盖哪一种中断窗口？
4. 为什么已持久化结果可以复用，而没有模型结果时必须确认重试？
5. 为什么恢复沿用任务 ID，重新生成使用新 ID？
6. 暂停请求与最终入库事务如何避免“已答应暂停却继续保存”的竞争？
