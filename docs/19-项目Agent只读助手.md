# 模块 19：项目 Agent 只读助手

本模块将已有查询能力交给 Agent 选择调用。入口是项目页面右上角「项目助手」，项目列表也有「助手」入口；同一项目的需求、知识库、用例等页面共用侧边栏和会话记录。

## 这一轮实现什么

- 原生 Function Tool Calls，LangGraph 编排「模型 → 工具 → 模型」，模型根据问题选择工具并整理答复。
- 当前项目的概况、需求列表/详情、人工版本用例、Judge 报告和知识检索，共六种内置只读工具。
- 后台持久化提问、对话记录、工具参数与结果快照；页面用 SSE 接收工具开始、完成、失败与轮次状态，断连后只读轮询。
- 当前项目由服务端上下文绑定。模型参数没有 `project_id`，需求 ID 还会再次验证所属项目；未知工具、额外参数和命令不可执行。

只读指不会改写需求、知识文档、草稿、人工结论或运行测试；对话与审计记录会保存至 SQLite。测试执行尚未接入时明确返回“暂无实测结果”，不会用零条统计冒充真实执行结论。功能点生成数量也不等于语义覆盖率。

## 先这样验收

1. 进入已有项目，点击右上角「项目助手」，提问「项目概况」。核对需求数和项目名称，展开 T1 查询结果。
2. 问「列出需求」「查看已采纳用例」「最近的 Judge 评估」。用例查询读取当前人工版本，Judge 会显示 Mock 来源与依据过期状态。
3. 项目有知识时问具体业务问题，例如「查询知识库里订单取消的规则」。真实模式复用混合检索：BM25、向量、RRF；工具参数可选择 Rerank，默认关闭。向量不可用时沿用已有明确降级逻辑。
4. 关闭助手后在当前项目切换页面，再打开；刷新页面后从会话下拉框选择历史，对话与工具快照仍在，读取不会再次调用模型。
5. 切换另一项目，核对会话与工具数据不串项目。删除项目会级联清理会话记录。
6. 可在生成模型设置显式开启 Mock，再重新打开助手。Mock 读取本地数据，知识只查 BM25，不调用生成、Embedding 或 Rerank 服务。验收后按需要关闭 Mock。
7. 若当前模型不支持原生 Tool Calls，页面应显示明确失败；不会自动改用 Mock。失败后的「复制问题到输入框」只填充文字，确认发送才是新一轮。

真实 Agent 复用已保存的生成模型地址、模型和 Key，无需再填配置。基础连接测试成功只表示对话接口可用，不保证工具协议兼容；应实际提问验证。DeepSeek 官方调用流程见 [Tool Calls 文档](https://api-docs.deepseek.com/guides/tool_calls/)。对官方 DeepSeek 地址，Agent 请求显式关闭 thinking；只保留答复与必要的工具协议字段，不保存 reasoning_content。

## 请求如何流转

```text
项目页面 → AgentDrawer → 创建/读取项目会话
提交 request_id + 问题 → SQLite 排队 → Agent worker
  → LangGraph model：发送 messages + tools
  → 原生 assistant.tool_calls
  → tools：校验白名单、参数和项目范围，保存开始记录
  → 统一只读适配层查询 → 保存结果/失败记录
  → role=tool + tool_call_id 返回模型
  → 模型继续查询或输出最终答复 → 保存轮次结果
SSE/只读轮询 → 页面更新工具过程和最终答复
```

首轮要求原生工具调用，至少有一次成功项目查询才允许保存最终答复。T1、T2 等标识关联本轮工具结果；答复是模型整理的文字，仍需展开结果核对。知识和需求正文作为不可信数据处理，不能修改系统规则或工具权限。

每个对话最多 50 轮，模型仅接收最近 4 轮成功问答文字；每轮都要求重新查询当前数据。历史工具结果是当时快照，不会随着文档或用例变更重写。每轮最多 4 次模型调用、6 次工具调用，单次响应最多 3 个工具；工具顺序执行。工具超时 45 秒，整轮最长 180 秒，模型沿用生成配置超时。

列表有数量上限，长正文/步骤有字段截断标记；工具结果正文超过 12000 字符时转为有明确截断提示的 JSON 预览。请求上下文上限 512 KiB，模型响应上限 1 MiB、答复最多 8000 字符。没有结果不等于不存在业务规则，需检查查询范围、截断和降级提示。

## 可靠性与当前边界

同一会话只能有一个活动提问；相同请求 ID 和相同问题幂等，页面未知提交结果时先刷新核对。一个后台 worker 串行执行 Agent 轮次，继续单进程部署。模型配置或流程版本变化会停止本轮后续调用。

关闭侧栏或刷新页面不取消后台任务，重新打开只恢复查看。服务停止或重启会将未完成轮次标为中断，不自动重放模型或工具；手动重新发送可能重复计费。Agent 本模块没有 checkpointer 或暂停/断点恢复，原有用例生成的节点检查点、暂停/恢复保持可用。

SSE 流传送工具事件和状态快照，最终答复完成后显示，当前没有逐 Token 文本流。服务端轮询事件表，极短工具可能在同一次刷新中同时显示开始和完成；审计保存各自时间。仅采集调用次数和本地耗时，不估算费用或补造 Token 数。

真实模式每轮可能多次调用生成模型，知识检索可能额外调用 Embedding/Rerank；Mock 明确不发这些外部请求。配置中的已知 Key 在问题、工具结果及答复中遮蔽，原始 HTTP 错误不回显。此版本仍是单人本地工作台，没有引入多用户鉴权。

外部 MCP 工具、写操作确认与测试执行在后续模块扩展。本轮固定六个内置工具，不能自行注册任意 URL、Shell 或外部服务。

## 阅读代码

1. `backend/app/prompts/project_agent.md`：项目范围、查询与答复规则。
2. `backend/app/agents/tools.py`：参数模型、原生工具 schema、六个只读 handler 和统一执行入口。
3. `backend/app/agents/protocol.py`：原生工具消息适配、严格边界与显式 Mock。
4. `backend/app/agents/workflow.py`：实际 LangGraph 循环和流程版本。
5. `backend/app/agent_sessions.py`：项目会话 API、幂等、队列、审计、SSE 和重启处理。
6. `backend/app/models.py`：会话、轮次、工具调用三张表。
7. `web/src/components/AgentDrawer.vue`、`web/src/App.vue`：共用助手与项目范围切换。
8. `backend/tests/test_agent.py`：隔离、协议、上下文、预算和失败处理。

## 升级与验证

版本 0.19.0，无新增依赖。重启后端自动创建三张新表，已有项目、用例、知识和配置保留；刷新前端后可打开助手。

2026-10-27：233 项后端测试通过（212 项回归 + 21 项 Agent 测试），前端类型检查与生产构建通过。覆盖原生工具往返、额外参数/跨项目 ID 拒绝、只读保护、人工版本筛选、共享混合检索、超时/大小/次数限制、未知工具、幂等与互斥、上下文、Key 遮蔽、失败与重启不重放及级联删除。

浏览器使用临时数据库和假模型传输验证：项目侧边栏、工具结果展开、刷新持久化且无重复调用、项目切换隔离、工具协议不兼容提示、复制问题不重试，以及 Mock 知识查询不增加外部调用。另用真实本地 HTTP 流验证 SSE 在结束前已返回状态和工具事件。未使用用户真实 Key 或额度，真实 DeepSeek 答复质量由用户验收。
