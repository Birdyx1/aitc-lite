# 模块 08：持久化生成任务与进度

后续进度：模块 09 已实现[节点检查点、暂停与恢复](09-节点检查点暂停与恢复.md)。以下保留模块 08 当时的范围与原理。

本模块把「等待一个生成请求返回」改为「先保存任务，再由后台工作协程执行」。仍然每次生成一个已确认功能点；保留原来的 LangGraph、草稿、人工评审和导出。

## 现在可以做什么

在「项目 → 需求 → 用例草稿」提交后，页面展示任务状态与阶段进度。提交成功后可以离开页面，后台继续执行；返回或刷新页面会重新从 SQLite 读取任务。成功后仍生成独立草稿，失败记录也保留。

同一需求同时只允许一个排队或运行中的任务。不同需求进入同一个本地队列，依次执行。相同请求 ID 及参数重复提交返回原任务；失败后再次点击生成会创建新 ID，显式重新调用模型。提交响应丢失时，页面保留原 ID，按钮显示「核实本次提交」。

目前支持单个应用进程、单个工作协程，适用于现有本地单人版本。请沿用 README 的启动命令，不使用多个 uvicorn worker 或同时启动多个进程访问同一 Lite 数据库。多进程租约和分布式任务队列不在本轮范围。

## 状态与进度

```text
queued 排队中 → running 运行中 → succeeded 已完成
                          ↘ failed 失败
服务停止/重启时未完成          → interrupted 已中断
```

| 阶段 | 页面进度 | 含义 |
| --- | ---: | --- |
| queued | 0% | 等待后台领取 |
| prepare | 5% | 检查输入并准备提示词 |
| generate | 25% | prepare 已完成，正在调用模型 |
| validate | 70% | 模型已返回，正在结构与策略校验 |
| save | 90% | 校验已完成，正在核对版本并保存 |
| completed | 100% | 草稿已提交数据库 |

这些数值标识工作阶段，不是模型输出比例，也不能用于估算剩余秒数。失败或中断时保留最后阶段、已完成节点和错误信息，不把进度改成 100%。Mock 执行很快，可能直接看到完成。

## 服务重启时的约定

启动时核对遗留的 queued/running 任务：

- 若已经存在同 ID、同请求指纹的完整生成结果，补记为 succeeded，避免出现「结果已保存，任务仍运行中」。
- 否则标为 interrupted，不自动重发模型请求。即使调用方没有收到结果，外部模型也可能已经执行和计费。
- 正常停止时取消工作协程并记录中断；异常退出留下的运行状态由下次启动核对。
- `--reload` 的代码重载同样属于服务重启，运行中的任务可能中断。

**任务记录持久化已实现；LangGraph checkpointer、暂停按钮和从节点断点恢复尚未实现。** 本轮仅持久化状态、阶段和完成节点，不保存模型原始响应作为可恢复检查点。下一模块先补节点检查点，再加入暂停和恢复。

## 请求与数据流

1. 前端生成请求 ID，提交功能点 ID、清单版本、输入哈希和策略。
2. `submit_task` 取得 SQLite 写锁，校验项目、需求、确认范围、模型配置和活动任务，再提交新任务；HTTP 202 表示已排队，HTTP 200 表示找到同一个旧任务。
3. 生命周期启动的 `task_worker` 每 0.25 秒查找最早排队任务，以条件更新领取为 running，串行执行。
4. `execute_task` 比较提交时模型配置的摘要。排队期间配置改变则明确失败，不改用另一份配置调用模型。
5. `run_generation` 继续运行原有 LangGraph，通过 `astream(..., stream_mode="values")` 获得节点完成状态，单独更新任务进度。
6. 模型调用期间不占用数据库写事务。调用后仍核对需求原文、功能点版本与确认状态，全部草稿一次保存。
7. 页面每 1.5 秒查询任务。完成后刷新草稿历史；正在编辑旧草稿时保留弹窗与输入，用户可稍后点击任务的「查看草稿」。离开页面后清理轮询计时器。

任务轮询失败时显示提示、保留原状态并重试，暂时禁用新提交。任务列表有手动刷新按钮。

## API

共同前缀：`/api/projects/{project_id}/requirements/{requirement_id}`。

| 请求 | 作用 |
| --- | --- |
| `POST /generation-tasks` | 提交任务，JSON 输入与原用例生成接口一致 |
| `GET /generation-tasks` | 按新到旧列出本需求任务 |
| `GET /generation-tasks/{task_id}` | 读取单个任务状态 |
| `GET /case-generations/{task_id}` | 成功任务对应的草稿结果 |

任务 ID 与结果生成记录 ID 相同，但两者保存在独立表中。历史草稿无需补造任务，仍在历史生成记录中查看。原同步生成 API 保留兼容，共用执行函数；页面已经改用任务 API。

新增 `generation_tasks` 表保存请求参数、功能点名称、模型来源、配置比较摘要、状态、阶段、完成节点、错误及时间。任务接口不返回内部请求参数或摘要。API Key 不保存到任务记录、任务输出或 LangGraph 状态中；执行时从现有模型配置读取。第三方原始错误体不落入任务表。

项目/需求删除会级联清理任务。生成期间删除来源时，后续节点停止或最终写入被拦截，不保留孤立草稿。已经发出的模型调用无法保证由删除动作撤销。

## 阅读顺序

1. `backend/app/models.py` 的 `GenerationTask`：任务与生成结果为什么分开存储。
2. `backend/app/generation_tasks.py`：提交、幂等、领取、进度、失败及启动核对。
3. `backend/app/main.py`：工作协程为什么随应用启动和停止。
4. `backend/app/case_generations.py` 的 `run_generation`：复用原执行链路，接入进度回调。
5. `backend/app/workflows/case_generation.py`：原有三个节点保持不变，尚无 checkpointer。
6. `web/src/api.ts` 和 `web/src/pages/CaseGeneration.vue`：任务提交、轮询和旧稿评审保护。
7. `backend/tests/test_generation_tasks.py`：使用受控模拟模型验证并发、错误和重启。

## 升级与验收

无新增依赖，重启后端自动创建任务表，原有项目、配置、草稿、评审均保留。服务端与前端版本为 0.8.0。

- [ ] 已确认功能点后点击生成，先出现任务；真实模型耗时较长时可看到「模型生成」。
- [ ] 任务未完成时，新生成按钮禁用；新标签页也不能为同一需求提交另一个活动任务。
- [ ] 提交成功后返回需求列表，再进入用例草稿页，任务仍存在；刷新同样可查询状态。
- [ ] 成功后显示完成及 100%，可查看草稿，继续人工编辑、采纳及导出。
- [ ] 模型错误或校验失败后显示失败原因，刷新后记录仍保留，原有草稿不变。
- [ ] 失败后重新点击生成，创建一个新任务，不自动重试旧任务。
- [ ] 生成期间停止后端再重启，旧任务显示中断，不自动触发新模型调用。
- [ ] 多个需求提交时，后续任务排队，前一个结束后执行下一个。
- [ ] 后台新任务完成时，正在编辑的旧草稿弹窗和输入保持。
- [ ] 切换项目不能访问其他项目的任务。
