# 模块 03：生成模型配置与连接验证

状态：已实现，待用户验收。先完成模型调用基础，再进入 AI 功能点拆解。

## 范围

本模块新增全局“模型设置”页面，保存一套生成模型配置。支持 API 根地址、模型名称、API Key、超时时间（5–60 秒）及显式 Mock 开关。后续 Agent 和专项 Skill 可以复用该配置；Embedding、Judge 和 Rerank 配置留到各自模块加入。

设置页的测试按钮只使用已保存配置。修改表单后要先保存，避免“测试的值”和“后续实际使用的值”不一致。连接验证发送一条固定短消息，不上传已有项目或需求；真实模式测试可能产生少量模型调用费用。

## 最小请求流程

1. 页面 `GET /api/settings/generation` 读取公开配置及 `has_api_key` 标记。
2. 用户填写表单，`PUT /api/settings/generation` 保存到本机 SQLite。
3. 用户点击测试，`POST /api/settings/generation/test` 由后端读取已保存配置。
4. Mock 模式直接返回明确标注的固定结果，不建立模型网络连接。
5. 真实模式通过 HTTPX 向 `<base_url>/chat/completions` 发起非流式请求。
6. 服务返回有效的 `choices[0].message.content` 文本后，页面展示模式、耗时和截取的回复；异常显示错误，不切换 Mock。

API 根地址应填写供应商给出的根路径，如自建服务的 `http://127.0.0.1:11434/v1`，不要填写完整的 `/chat/completions` 地址。模型名称须是该服务实际支持的标识；本模块不维护供应商和模型列表。

本模块测试兼容 Chat Completions 的文本响应，不表示已经验证工具调用、结构化输出或业务生成质量。当前连接为后端直接出网，不自动读取环境中的 HTTP 代理配置。只有 Responses 接口或使用其他鉴权方式的服务不在本模块范围内。

## DeepSeek 官方 API 填写示例

2026-10-26 核对 [DeepSeek 官方文档](https://api-docs.deepseek.com/)：关闭 Mock，API 根地址填 `https://api.deepseek.com`，模型名称填 `deepseek-flash`，API Key 填自己在 DeepSeek 开放平台创建的 Key，超时可先设 60 秒。先保存，再点击“测试真实连接”。不要把 `/chat/completions` 填进根地址，不需要给 Key 添加 `Bearer ` 前缀。

官方当前模型默认开启思考模式。连接测试针对官方域名显式设置 `thinking: {"type": "disabled"}`，以便短测试消息及时产生正文；此规则仅用于连接探针，不代表后续业务生成的思考策略。参考：[官方参数说明](https://api-docs.deepseek.com/api/create-chat-completion/)。

## Key 的保存语义

| 操作 | 结果 |
|---|---|
| 输入新的非空 Key 并保存 | 创建或替换保存的 Key |
| Key 留空并保存其他配置 | 保留原 Key |
| 勾选“清除已保存的 API Key”并保存 | 删除原 Key |
| 修改 API 根地址 | 有旧 Key 时必须替换或清除，避免误发给新地址 |

Key 保存在 Lite 自己的本地 SQLite 文件中，当前未做数据库加密，应按包含凭据的文件管理，不提交或分享。该目录已被 `.gitignore` 排除。页面使用密码输入框，API 响应只返回是否已配置；读取、保存、参数校验错误和模型错误均不回显 Key。

本地免鉴权模型可以不填 Key，此时后端不发送 Authorization 头。测试超时、鉴权失败、限流、异常状态、无效 JSON 或空回复均为失败。后端不返回服务端原始错误体，不跟随重定向，也不自动重试。Mock 不会在缺少 Key 或真实调用失败时自动开启。

## 代码导读

1. `backend/app/models.py`：`GenerationSettings` 单行配置，ID 固定为 1。
2. `backend/app/schemas.py`：输入校验、`SecretStr` 和公开输出；`SecretStr` 限制调试表示，但不会自动加密数据库。
3. `backend/app/settings.py`：读取、保存、保留/替换/清除 Key 的规则。
4. `backend/app/llm.py`：不可变的配置快照、Mock 分支、真实 HTTP 请求、超时与错误处理。
5. `backend/app/main.py`：配置接口注册；针对设置请求的 422 不回显原始输入。
6. `web/src/pages/Settings.vue`：表单、未保存提醒、保存/测试状态和结果展示。
7. `web/src/api.ts`：类型及设置请求，连接测试的前端等待时限长于后端模型超时。
8. `backend/tests/test_settings.py`：临时数据库及 `httpx.MockTransport` 模拟外部模型。

配置是全局单人配置，不放入某个项目。当前使用 HTTPX 做最小连接测试；实际业务的 LangChain 和 LangGraph 适配在后续模块加入，沿用同一份配置。

## 启动与升级

沿用 README 的双终端方式。HTTPX 已从开发依赖移入运行依赖；在 `aitc-lite/` 下执行：

```bash
source .venv/bin/activate
python -m pip install -r backend/requirements-dev.txt
```

后端启动会新增 `generation_settings` 表，不更改既有项目或需求表。前端进入 `/settings`，或点击侧栏“模型设置”。

## 手工验收

- [ ] 首次打开显示“尚未配置”，不会默认启用 Mock，测试按钮不可用。
- [ ] 真实模式下缺少根地址或模型名称时，保存被拦截。
- [ ] 打开 Mock，保存后显示“已保存 · Mock 模式”；验证结果明确标明未联网。
- [ ] 刷新页面或重启后端，已保存配置仍存在。
- [ ] 关闭 Mock，输入自己服务的根地址、模型名称和 Key；保存后 Key 输入框变空，只显示“已配置”。
- [ ] 测试真实连接，成功后显示真实调用、耗时和回复；此步骤使用用户自己的服务与凭据。
- [ ] 修改表单，测试按钮禁用；保存或重新加载后可再次测试。
- [ ] Key 留空保存模型名称修改，旧 Key 仍保留；换一个新 Key 保存则替换旧值。
- [ ] 勾选清除 Key 后保存，显示“未配置 Key”；本地免鉴权服务仍可测试。
- [ ] 有旧 Key 时更换根地址但不替换/清除 Key，保存被拒绝，原配置保持。
- [ ] 用错误 Key 或不可达服务测试，显示失败且仍为真实模式；不会产生 Mock 成功结果。
- [ ] 修改表单后离开页面或点“重新加载”，出现未保存提醒；取消后输入保留。
- [ ] 配置加载失败后不展示可编辑的默认空表单；保存失败时当前输入仍保留。
- [ ] 项目和需求页面仍可进入，现有数据保留。
