# 模块 10：项目知识文档入库与分块

后续进度：模块 11 已实现 [BM25 关键词检索](11-BM25关键词检索.md)。以下保留模块 10 当时的范围。

本模块先准备后续检索的数据来源：每个项目可以保存知识文档、查看原文与分块、修改后重新分块，以及删除文档与全部分块。

入口：项目列表 →「知识库」，或需求页面 →「项目知识库」。

## 当前范围

- 手工粘贴知识正文，或导入 UTF-8 的 `.txt`、`.md`、`.markdown` 文件。
- 新建、查看、编辑、标题/来源文件名筛选和删除，保存后自动分块。
- 保存原始换行、缩进、文档版本、内容 SHA-256、分块 ID 和原文偏移。
- 文档与分块一起提交；修改失败整体回滚，不留下半份新数据。
- 读取与操作始终限定当前项目；项目删除会清理其全部文档与分块。

**本轮未建立向量或 BM25 索引，没有 RRF/Rerank，也没有向用例生成注入知识。** 页面明确展示当前范围。知识库使用已有 SQLite，不调用 DeepSeek 或其他模型，不增加服务和依赖。

Word、PDF、扫描件、网页抓取、批量文件导入、Markdown 结构解析后续按需扩展。当前 Markdown 作为原文文本保存、展示，不执行 HTML 或脚本。

## 输入与文件导入

| 项目 | 限制 |
| --- | --- |
| 标题 | 1–200 个 Unicode 字符，首尾空白去除 |
| 正文 | 1–100000 个 Unicode 字符，不能全为空白 |
| 本地文件 | 最大 512 KiB，必须是有效 UTF-8 文本 |
| 来源文件名 | 最长 255 个字符，仅为标签，不允许路径及控制字符 |

浏览器读取并解码所选文件，UTF-8 BOM 会去除；点击保存前不写入后端。读取失败保留原有输入。后端收到的是标题、正文和来源标签的 JSON，不按文件名读取服务器文件，也不保存原始二进制文件。标题空白时以文件名自动填充。

`source_filename` 表示导入来源；人工编辑后正文可能不同于原文件。当前内容摘要由实际保存正文计算。

未保存的修改在关闭编辑器、离开页面或刷新时有提醒。保存失败保留内容。新建请求沿用编辑器内的同一个文档 ID，响应丢失后直接重试相同内容不会重复入库。若保存结果不确定后又更改内容，应先核实列表；不能用相同 ID 覆盖已经保存的另一份正文。

## 分块规则

实现位于 `backend/app/knowledge/chunking.py`，版本 `boundary-chars-v1`。

1. 每块最多 800 个 Unicode 字符，不是 800 个模型 token。
2. 尚未到文末时，在窗口后 40% 中寻找切分位置：优先段落分隔，再选换行、句末和空格；没有合适边界时按上限硬切。
3. 下一窗口从上一窗口结束位置往前 120 字符开始，保留上下文重叠。
4. 纯空白窗口不保存为知识块。原始全文依然保留；所有非空白内容仍被覆盖。
5. 序号从 1 开始，偏移从 0 开始，区间为 `[start_offset, end_offset)`，结束位置不包含。

验证一块是否来自原文：

```python
chunk_text == document_content[start_offset:end_offset]
```

偏移按 Unicode 字符计数。JavaScript 字符串索引通常按 UTF-16 计数，遇到 Emoji 时请先转换：

```javascript
Array.from(documentContent).slice(startOffset, endOffset).join('')
```

每块记录 SHA-256。分块 UUID 由文档 ID、文档版本、分块器版本、序号、偏移和内容摘要确定。同一文档版本重算保持相同 ID；文档有修改并保存后版本增加，所有旧分块被删除，新分块使用新 ID。将来检索服务据此核对索引是否仍对应有效分块。

本算法方便学习与追溯，不理解表格、代码结构和完整业务语义，也不把字符数当作 token 数。后续可以版本化替换分块器。

## 保存与版本冲突

新增两张表：

| 表 | 保存内容 |
| --- | --- |
| `knowledge_documents` | 项目、标题、全文、来源、revision、摘要、字符与分块数量、分块参数及时间 |
| `knowledge_chunks` | 文档外键、文档版本、稳定块 ID、顺序、原文偏移、内容及摘要 |

新建时先取得 SQLite 写锁，检查文档请求 ID，再在一个事务中写文档和分块。重复相同请求返回原文档，参数不一致返回 409。

编辑时提交 `expected_revision`。后端取得写锁后读取最新版本；旧版本请求返回 409，不能覆盖。内容、标题、来源或分块器版本有变化时，revision 加一，删除旧块并写新块，最后一起提交。完全没有变化的保存不增加版本或重新分块。

删除同样要求 `expected_revision`：列表过期时不能直接删除后来修改过的文档，须刷新核实。删除前提示不可恢复，并说明全部分块将一并删除。

本轮没有索引缓存，因此更新/删除直接清理知识表中的旧分块；后续增加 BM25、向量索引时仍需实现对应的索引更新或失效与有效块校验，不能仅依赖本轮数据库删除。

## API

共同前缀：`/api/projects/{project_id}/knowledge-documents`。

| 请求 | 作用 |
| --- | --- |
| `GET /` | 文档摘要列表，不包含全文和分块正文 |
| `POST /` | 新建并分块；首次 201，同 ID 相同参数重放 200 |
| `GET /{document_id}` | 原文、摘要、版本和按顺序排列的全部分块 |
| `PUT /{document_id}` | 校验版本，原子更新文档与分块 |
| `DELETE /{document_id}?expected_revision=1` | 校验版本后删除，成功 204 |

新建输入示例：

```json
{
  "document_id": "用 crypto.randomUUID() 产生的 UUID",
  "title": "登录规则",
  "content": "验证码有效期为五分钟。错误码 E1001 表示验证码已过期。",
  "source_filename": "登录规则.md"
}
```

编辑不传 `document_id`，改传 `expected_revision`。404 表示项目或该项目下的文档不存在；409 表示请求 ID 或版本冲突；422 表示字段、字符数、编码或参数无效。校验错误不回显整份知识正文。

## 阅读顺序

1. `web/src/pages/ProjectKnowledge.vue`：文件读取、输入保护、列表、原文和分块预览。
2. `web/src/api.ts` 的 `knowledgeApi`：新建 ID、版本参数和 API 请求。
3. `backend/app/schemas.py` 的 `Knowledge*`：输入及输出约束。
4. `backend/app/knowledge/chunking.py`：边界、重叠、原文位置和稳定 ID。
5. `backend/app/knowledge_documents.py`：项目范围、幂等、版本锁和事务。
6. `backend/app/models.py` 的两张知识表：关系与级联删除。
7. `backend/tests/test_knowledge.py`：验证内容覆盖、并发和事务回滚。
