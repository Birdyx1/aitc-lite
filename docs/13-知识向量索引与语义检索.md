# 模块 13：知识向量索引与语义检索

本模块把已保存的知识分块送入独立 Embedding 服务，在本机 Chroma 中持久保存向量，支持项目内的语义检索、相似度展示及来源定位。BM25 保持独立；RRF 融合、Rerank 和生成时的 RAG 注入继续作为后续模块。

## 使用与验收

1. 在「Embedding 配置」确认真实配置已保存并通过连接测试。你当前选择的硅基流动 `BAAI/bge-m3` 可继续使用，不需要改 DeepSeek 的生成配置。
2. 进入「项目 → 知识库」，添加几份主题不同的业务规则，例如验证码、退款和权限。
3. 在「向量索引与语义检索」点击「构建向量索引」，阅读调用提示并开始。每批最多 16 个分块，观察排队、构建进度和完成数量。刷新或离开后返回仍能查看最近任务。
4. 使用不同于原文的问法，例如原文“验证码五分钟内有效”，查询“登录短信失效后怎么处理”。比较向量结果和 BM25 的差异。语义质量取决于模型和知识内容，需要你用真实配置验收。
5. 点击结果的「查看来源与命中分块」，确认文档版本、原文内容、位置和高亮块一致。
6. 修改或删除文档，刷新索引状态，应提示重建，旧检索结果清空、语义查询不可用。重建后再查，确认没有旧版本内容。
7. 切换到另一个项目，确认不能查询前一个项目的索引。
8. 显式开启 Mock 并重建时，应显示“不具备语义检索能力”。切回真实配置后需重新构建。

真实构建会发送当前项目所有有效分块正文；每次语义查询发送查询文本。只在主动点击后调用服务，不自动重试，不自动切换 Mock。请先使用少量文档观察效果。构建目前为全量重建，不复用上一轮向量。

## 请求链路

```text
GET  /api/projects/{project_id}/vector-index
POST /api/projects/{project_id}/vector-index/builds  {request_id: UUID}
POST /api/projects/{project_id}/vector-index/search  {query, top_k}
```

构建请求先写 SQLite 任务并返回 202。单进程工作协程读取当前分块快照，分批调用模块 12 的 `embed_texts`，把返回向量写入新建的 Chroma collection。不同批次必须保持相同维度，所有向量继续经过数量、索引、有限数值和非零校验。

所有批次完成后，在 SQLite 写锁内重新核对项目、语料摘要和模型配置，再把 `vector_indexes.collection` 指向新 collection，同时将任务改为成功。查询只读取已发布索引；失败或中断的半成品不会成为可查询索引。若原来的索引仍对应当前语料和配置，重建失败不会破坏它。

搜索先校验索引版本，再调用一次查询 Embedding，使用 Chroma 的 cosine 距离检索。页面展示 `相似度 = 1 - distance`，范围约为 -1 到 1。最后重新核对语料、配置及索引指针，并从 SQLite 当前项目分块补充正文和来源。

## 数据与失效

| 存储 | 内容 |
| --- | --- |
| `vector_builds` | 请求标识、项目、排队/执行/成功/失败/中断、已完成分块数、语料与配置摘要、脱敏错误 |
| `vector_indexes` | 每项目一条已发布索引指针、语料摘要、向量空间摘要、实际维度、模型和分块数 |
| `backend/data/aitc-lite-chroma/` | 本地 Chroma 向量与分块 ID；不保存 API Key，不让 Chroma 自动下载或调用默认模型 |

- 向量空间摘要包含服务根地址、模型名、Mock 模式、预期维度及适配版本。Key 和超时调整不改变索引身份。
- 文档新增、修改、删除会改变有效分块摘要，旧索引立即在后端检索校验中失效。页面本地操作后刷新状态；外部修改最多约 10 秒反映到状态栏，也可手动刷新。
- 文档变化不立即逐条删除 Chroma 中的旧向量；它们无法通过旧索引检索。成功重建后回收旧 collection，项目删除后在空闲清理中回收。中断半成品在后续清理或重启时回收。
- 相同 `request_id` 的重试只核对已有任务，不重复提交；同项目只允许一个排队或执行中的构建。
- **构建暂不支持暂停和断点续传**。服务停止或重启后，未完成构建标为中断；需要手动全量重建，可能重复计费。模块 09 的用例生成检查点和暂停/恢复保持可用。
- 继续采用单人本地、单进程部署方式。备份时停止服务，并同时保存 SQLite 与 Chroma 目录；单独复制其中之一不能保证索引对应。

## 阅读顺序

1. `web/src/components/VectorSearchPanel.vue`：提交、状态轮询、结果失效和来源事件。
2. `web/src/api.ts`：接口类型与超时。
3. `backend/app/vector_search.py`：接口、分批任务、影子索引发布和竞态校验。
4. `backend/app/knowledge/vector_store.py`：Chroma 持久客户端、显式向量写入和 cosine 查询。
5. `backend/app/embeddings.py`：复用模块 12 的服务适配与向量校验。
6. `backend/tests/test_vector_search.py`：临时 SQLite、真实本地 Chroma 与模拟 HTTP 服务的集成测试。

## 安装与验证

在 `aitc-lite/` 下更新依赖，重启后端。已有表不改写，启动时自动新增两张表。

```bash
.venv/bin/python -m pip install -r backend/requirements-dev.txt
cd backend
../.venv/bin/python -m unittest discover -s tests -v
```

本模块固定 `chromadb==1.5.5`。为保留原有 `pydantic==2.10.4`，同时固定兼容的 `pydantic-settings==2.7.1` 与 `kubernetes==32.0.1`（Chroma 间接依赖，不代表部署 Kubernetes）。独立 `.venv` 已安装，`pip check` 通过。

## 学习问题

1. 为什么索引必须记录模型配置，而不能只检查维度相同？
2. 为什么分批写入后还需要单独“发布”新索引？
3. 为什么文档变更后不能把部分旧结果继续当作完整检索结果？
4. 为什么相似度较高仍不能保证内容能回答问题？
