# 模块 23：项目工作台与下一步指引

版本 0.23.0。点击项目列表的项目名称进入工作台；原「需求」「知识库」等快捷入口继续保留，顶部导航新增「项目工作台」。直接刷新地址 `/projects/{projectId}/overview` 仍可加载。

本模块将已经实现的能力汇总成只读验收入口，不会自动写需求、调用模型、连接 MCP 或创建任务。用户已选择先完成工作台，稍后提供真实需求；本轮没有向「商城订单系统」插入演示规则。

## 页面展示什么

- 当前项目需求数量、有效确认的需求和功能点。
- 生成批次、真实/Mock 来源、当前版本功能点生成数量，以及草稿待评审/采纳/驳回数量。
- 知识文档和有效分块数量、生成和向量任务状态。
- Judge 报告数量与状态，不将评分报告当成实测结论。
- 人工执行任务和条目统计；通过率沿用通过 /（通过 + 失败），分母为零显示「—」。
- 独立评测样本、真实模式/Mock 运行及状态，不将运行结束当成全部样本成功。
- 生成、Embedding、Rerank、Judge 的已保存字段状态；Judge 默认复用或独立来源。
- MCP 项目绑定、当前版本绑定和已启用目录工具数量。

工作台复用 Agent 项目概况的统计，再补充确认、配置、评测和下一步信息；没有使用另一套 AI 汇总。所有查询在同一个短读快照完成，返回或报错前释放读事务。

## 下一步如何选择

按固定规则提供一条操作建议，并始终保留其他入口：

1. 无需求：录入第一条真实需求。
2. 有未完成生成任务（含暂停）：先查看任务，不重复发起。
3. 需求尚未有效确认或原文变化：核对功能点范围。
4. 有待评审草稿：先人工评审，避免立即生成更多批次。
5. 当前已确认功能点缺少对应版本生成记录：进入需求生成页；若生成配置字段不完整则先完善配置。
6. 没有采纳用例：核对评审结论，必要时重新生成，不自动采纳。
7. 有采纳用例但没有人工执行任务：创建快照任务；有未结束任务则继续记录。
8. 人工任务已结束后，引导维护独立评测样本、准备运行或查看正在进行的评测。
9. 只有 Mock 评测时明确标注其局限；已有真实模式记录也只引导查看结果，不声明项目已通过。

这是当前数据的操作建议，不是强制流程或质量门禁。知识库、MCP、评测等可按需要通过导航直接进入；工作台不会补造缺失需求或在点击页面时自动执行操作。

“有效确认”同时检查确认标记与当前需求内容哈希。原需求变更后旧批次仍保留，但不再计入当前版本功能点的生成记录。计数不是需求语义覆盖率。

## 配置状态的边界

- 已保存真实配置：本机已有对应根地址与模型字段；不表示网络、Key、权限、额度或工具协议已验证。
- 已保存 Mock 配置：显式模拟模式，不代表真实模型可用。
- 待完成配置：缺少运行所需的本地字段。
- MCP 只统计启用服务、目录版本一致且按当前项目授权的工具。新目录或服务配置变化使旧绑定失效；不在工作台自动发现或重连。

接口不返回 Key、模型名、端点、命令、环境变量或原始工具参数；设置页仍负责具体配置和主动连接测试。工作台不会触发外部请求，也不修改全局 Mock 开关。

## 验收步骤

1. 点击「商城订单系统」项目名称，应进入工作台，而非直接进入需求页。
2. 该项目当前没有需求时应显示「录入第一条需求」，卡片数量为实际的零，人工通过率显示「—」。
3. 点击「去处理」进入本项目需求页；点击顶部「项目工作台」返回。刷新后数据一致，浏览器没有产生业务写入请求。
4. 后续你提供并保存需求后，刷新检查引导是否随确认、生成和评审状态变化。
5. 用其他项目核对统计隔离；不要把项目 A 的执行或评测数量显示到项目 B。
6. 有真实配置也不应显示“连接成功”；没有执行记录也不应显示“100%通过”。

真实操作验收继续参照 [集成验收与学习路线](集成验收与学习路线.md)。本轮先完成入口与状态展示，真实需求原文由用户稍后提供。
