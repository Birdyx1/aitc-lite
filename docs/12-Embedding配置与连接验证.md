# 模块 12：Embedding 独立配置与连接验证

入口：侧栏「Embedding 配置」，或知识库中的配置链接。页面地址为 <http://127.0.0.1:5174/settings/embedding>。

按照最小模块验收节奏，本轮先完成 Embedding 配置与协议验证。知识分块向量化、向量索引和语义检索作为下一模块，不在本轮一次性交付。

## 为什么单独配置

生成模型返回文字，Embedding 模型把文字转成数字向量，两者使用不同接口和模型标识。当前 DeepSeek 用例生成配置继续保留，Embedding 不读取、复制或覆盖它的根地址、模型或 Key。

需要提供兼容 `POST /embeddings` 的服务配置；不能仅因为一个服务能生成对话，就假定同一个模型能生成向量。也可以先显式开启 Mock，学习保存和验证流程。

本轮新增一张 `embedding_settings` 表，使用现有 HTTPX，无新依赖或外部服务自动安装。向量只在测试调用内存中处理，不落库、不显示完整向量、不改变知识分块或现有 BM25 行为。

## 如何填写

| 字段 | 填法与含义 |
| --- | --- |
| Mock 模式 | 开启后本地生成哈希示例向量，不联网、不具备语义能力 |
| API 根地址 | 支持 Embedding 的服务根地址，例如已部署本地服务的 `http://127.0.0.1:11434/v1`；不要包含 `/embeddings` |
| 模型名称 | 服务实际支持或已部署的向量模型完整标识 |
| Embedding API Key | 本服务的独立 Key；免鉴权服务可留空 |
| 预期向量维度 | 可留空，接受实际返回维度；填入 1–32768 时检查返回是否一致 |
| 超时 | 5–60 秒，包含请求及响应读取 |

根地址只允许 HTTP/HTTPS，不含账号密码、查询参数或 URL 片段。接口协议参考 [Ollama 的兼容接口说明](https://docs.ollama.com/api/openai-compatibility)。页面示例不代表本机已经安装或启动对应服务，需要按实际服务填写。

预期维度**仅用于校验**，不在请求中发送 `dimensions`，不会要求服务缩短或改变输出。不同提供商的可选参数兼容性不同，本轮只发送最小 float 向量请求。

保存后测试按钮才可用，有未保存修改时不能用旧配置测试。测试结果只保留在当前页面，刷新后清除；「已保存」标记不代表连接曾验证通过。

## Key 的处理

- 留空保留原 Key，输入新值替换，勾选清除后保存才清除。
- GET 只返回 `has_api_key`，不返回 Key 原文。保存成功后密码输入框清空，刷新也不会读回原文。
- 更换根地址时，必须同时替换或清除原 Key，防止旧服务凭据被带到新地址。
- 配置校验错误、服务原始响应和网络异常文本不会回显 Key。
- 与已有生成设置一致，Key 保存于本机 SQLite，不写入前端持久存储或 LangGraph 检查点。

保存失败保留输入；离开或刷新未保存页面会提醒。Embedding 保存不修改生成配置。

## 连接测试检查什么

真实模式只发送两段固定短文本：

```text
验证码过期后需重新获取。
登录验证码失效，请重新申请。
```

不发送项目、需求或知识文档正文。请求示例：

```json
{
  "model": "已配置的向量模型",
  "input": ["验证码过期后需重新获取。", "登录验证码失效，请重新申请。"],
  "encoding_format": "float"
}
```

向根地址追加 `/embeddings`，有独立 Key 时附带 Bearer 认证。一次批量请求，不自动重试、不跟随重定向，也不在失败时自动切换 Mock。

收到响应后：

1. `data` 数量应与输入数量一致。
2. 每条 `index` 应是范围内的整数、不重复，允许返回顺序不同。
3. `embedding` 应是非空数字列表，不接受布尔、字符串、NaN、无穷或零向量。
4. 维度为 1–32768，批内一致，填写预期维度时还需与预期匹配。
5. 归一化使用缩放后计算范数，避免非常大或非常小的有限数值溢出/下溢。
6. 响应读取上限 5 MiB；不兼容数据返回明确错误，原始服务错误体不返回前端。

页面只显示模式、向量数量、实际维度和耗时。**连接与向量格式验证通过，不代表召回质量已验证。** Mock 的哈希向量只证明流程可运行，不是语义检索模型。

## API 与代码导读

| 请求 | 作用 |
| --- | --- |
| `GET /api/settings/embedding` | 读取公开配置及是否保存 Key |
| `PUT /api/settings/embedding` | 保存独立配置；错误输入返回脱敏 422 |
| `POST /api/settings/embedding/test` | 用已保存配置执行固定双文本验证 |

未配置返回 400；访问拒绝、限流、协议或维度错误返回 502；超时返回 504。服务端 HTTP 错误会展示状态或分类，不回显原始错误体。

阅读顺序：

1. `backend/app/models.py` 的 `EmbeddingSettings`：为什么与生成设置分表。
2. `backend/app/schemas.py` 的 `EmbeddingSettingsInput`：根地址、独立 Key、维度和超时约束。
3. `backend/app/embedding_settings.py`：保存、公开输出和固定探针。
4. `backend/app/embeddings.py`：网络调用、批量索引校验、向量归一化与 Mock。
5. `web/src/pages/EmbeddingSettings.vue`：输入、保存、测试及未保存提醒。
6. `backend/tests/test_embedding_settings.py`：服务模拟、配置隔离、数值边界与错误处理。

`create_app` 新增独立的 `embedding_transport` 测试注入点，不复用 `llm_transport`。测试由本地模拟响应验证，不使用用户真实模型凭据。
