# 模块 16：RAG 上下文注入与引用追溯

本模块将项目知识检索接入已有的用例生成工作流，保存注入快照和 AI 原稿声明的引用。RAG 默认关闭，历史生成方式继续可用。专项 Skill 与 AI Judge 按后续模块继续实现。

## 使用与验收

1. 在「项目 → 知识库」保存几份相关业务规则。先用混合检索确认关键词、来源和排序合理；使用向量召回时先构建索引。
2. 在「需求 → 用例草稿」选择已确认功能点，勾选「使用项目知识 RAG」。填写知识查询，例如“验证码有效期”；留空会用功能点名称、描述、验收标准和需求标题构造最多 200 字符的查询。
3. 选择注入 1–5 个分块，默认 3 个。需要精排时勾选「知识检索使用 Rerank」。检索使用模块 14–15 的同一服务与降级规则，不另建一套召回逻辑。
4. 点击生成。准备输入阶段先检索并保存知识快照，再调用生成模型。真实模式可能依次调用 Embedding、Rerank 和生成模型；生成模型接收需求、所选功能点和入选正文。
5. 草稿生成后查看「知识注入与引用追溯」：查询、注入数量、检索/精排状态、每条原稿声明的 K1/K2 引用，以及来源标题、版本、原文位置、正文和分块摘要。
6. 对比“已注入”与“已引用”：注入分块不一定都被使用；模型没有使用时允许声明空引用。引用 ID 已校验属于本次注入，但引用是否能支持业务结论仍需人工核对，后续 Judge 再扩展质量检查。
7. 生成期间点击暂停，等待当前节点完成。刷新后恢复，确认复用已保存知识和模型结果，不重复检索或生成已完成节点。
8. 修改或删除知识文档，再查看历史草稿。历史正文与引用保留，并显示来源已更新/删除和依据过期；新采纳会被阻止，已采纳历史记录仍保留。

未配置向量或索引过期时，可使用当前项目 BM25，并记录降级原因；精排失败保留 RRF。不要把“使用了 RAG”当作质量保证，先验收检索与正文规则。

## 无知识时是否继续

默认检索无候选会停止，不调用生成模型。你可以调整查询、补充知识，或关闭 RAG 再生成。

若主动勾选「检索无命中或不可用时，允许无知识继续生成」，则无候选或双路服务不可用时，可以不注入知识继续。页面和快照明确记录原因、注入 0 块和空引用。来源版本冲突和项目删除不会降级为成功，仍分别返回 409/404。

这与正常单路降级不同：单路成功仍有有效候选时，会注入这些候选；无知识降级则不声称使用了任何资料。没有自动关闭 RAG、自动启用 Mock 或自动重试。

## 流程与检查点

```text
准备输入：核对需求/功能点 → 可选混合检索/精排 → 保存知识快照 → 拼装 Prompt
    ↓ 检查点，可暂停
模型生成：复用原生成配置 → 接收结构化用例和引用 ID
    ↓ 检查点，可暂停
结构与策略校验：原策略检查 + 引用 ID 检查
    ↓ 检查点，可暂停
写锁内再次核对来源 → 整批保存草稿与引用关联
```

保持 `prepare → generate → validate` 三个节点，准备阶段现在可包含检索。暂停会等待当前检索或模型节点完成；快照在 Prompt 检查点之前先落库，因此即使恰好在两次持久化之间中断，恢复也能复用已保存资料。

新增 `generation_knowledge` 表，按请求 ID 关联需求，保存请求指纹、检索快照、调用待核对标记和草稿 ID 到引用 ID 的映射。不修改已有业务表结构；删除需求或项目会级联清理相关快照，单独删除知识文档不会删除历史快照。

如果检索调用已开始但没有可复用快照，任务会显示“上次知识检索未留下快照”。恢复前需要确认可能重复计费；后端也校验此确认，不能只依赖前端提示。生成模型未知调用结果继续使用模块 09 的确认机制。两类调用分别记录，已完成结果不重复付费。

升级后工作流版本发生变化：旧版未完成任务不能套用新图恢复，需要重新发起；历史成功草稿仍可查看。此限制与模块 09 的流程版本保护一致，不伪造旧检查点。

## 请求参数与兼容性

原 `/generation-tasks` 和 `/case-generations` 请求新增：

```json
{
  "use_rag": true,
  "rag_query": "验证码有效期",
  "rag_top_k": 3,
  "rag_rerank": false,
  "rag_allow_empty": false
}
```

其余请求标识、功能点、版本、输入哈希和策略字段不变。不传新字段时默认关闭 RAG；关闭时保持旧请求指纹，已有成功请求可以安全重放。

任务恢复请求新增 `retry_uncertain_knowledge_call`，默认 false。它与原有的 `retry_uncertain_model_call` 分别确认知识检索和生成模型的未知调用结果，不自动批准任何重复请求。

生成详情新增 `knowledge`：未使用或无历史快照时为 null，否则包括查询、语料摘要、召回/精排轨迹与参数、向量和精排模型标识、来源分块及每条 AI 原稿引用。`current_status` 是读取时与当前文档比较的结果，不改写历史正文。

RAG 开启后的提示词版本为 `case-writer-rag-v2`。只把入选分块的 K 编号、标题、版本和正文注入模型，最多 5 × 800 个正文字符；不会发送整个知识库。检索快照可记录更完整的排序元数据，API Key 不进入快照或图状态。

## 引用与一致性边界

- 需求、功能点与知识均作为数据处理。提示词要求忽略知识中的角色、命令和输出格式要求，需求与确认范围优先；冲突写待澄清，不擅自改业务规则。
- RAG 输出允许每条用例增加 `knowledge_refs`，内容只能是本次 K 编号；未知或重复 ID 使校验失败，整批草稿不保存。没有依据时允许空数组；没有注入分块时不允许伪造引用。
- K 编号只在本次生成中有效，历史追溯依靠真实文档/分块 ID、版本、位置、内容摘要及原文快照。
- 保存快照、调用生成模型前、最终入库时核对语料变化；恢复也核对已保存快照。知识变化后不重新检索并混用旧模型结果，要求重新生成。
- 当前以整个项目有效分块集合判定知识依据是否过期，因此新增或修改未引用的文档也可能标记过期。这是本模块的保守策略。
- 模型引用声明不是引用正确性证明，注入列表也不是“全部被模型使用”的证明。人工编辑不自动重写 AI 原稿引用；页面明确说明引用针对原稿。
- 当前在生成详情保存和展示引用。已采纳列表可进入来源需求的生成记录查看；现有 Excel/Markdown 导出字段保持原格式，不额外导出知识全文。

## 学习顺序

1. `backend/app/hybrid_search.py`：抽出 `retrieve_hybrid`，页面检索与生成共用它。
2. `backend/app/rag.py`：先标记调用、保存快照、复用与当前来源比较。
3. `backend/app/workflows/case_generation.py`：在准备节点注入上下文，校验引用 ID。
4. `backend/app/case_generations.py`：模型调用前与入库前保护、草稿引用关联、历史证据输出。
5. `backend/app/generation_tasks.py`：恢复保护与检索重复调用确认。
6. `web/src/pages/CaseGeneration.vue`、`components/KnowledgeEvidence.vue`：主动开关和注入/引用对照。
7. `backend/tests/test_rag.py`：隔离项目、快照、引用、无知识降级、暂停恢复与竞态验证。

版本 0.16.0，无新增依赖。重启后端自动创建新表，前端刷新即可看到 RAG 选项。

2026-10-27：180 项后端测试通过（160 项回归 + 20 项本模块测试），前端类型检查与构建通过。覆盖注入与引用、历史持久化、ID 重放及指纹兼容、项目隔离与上限、未知/重复引用、来源更新/删除、采纳保护、无命中阻止生成、明确无知识降级、Mock、参数脱敏、检查点复用及未知检索确认。

浏览器使用临时数据库和模拟服务验证 RRF + Rerank 注入、引用展开、暂停/刷新/恢复、来源删除后的历史快照，以及明确无知识降级。暂停前后计数均为生成 1 次、Embedding 2 次（含建索引 1 次）、Rerank 1 次，证明恢复没有重复调用。未使用用户真实 Key 或额度；真实引用质量需通过本模块验收。
