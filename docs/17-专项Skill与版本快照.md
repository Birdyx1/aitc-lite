# 模块 17：专项 Skill 与版本快照

本模块增加两个可选业务专项：接口测试（`api`）与安全/权限（`security`）。可以分别或同时开启，也可以不选择、继续普通生成。专项采用固定注册表、独立 Prompt 和 handler，复用生成模型；不做运行时安装、发现或插件市场。

这里的 Skill 是 AITC Lite 内的测试设计模块，不是 Codex 的个人技能，也不读取外部 `SKILL.md` 或执行上传代码。

## 使用与验收

1. 进入「需求 → 用例草稿」，先确认当前功能点范围。
2. 不选专项生成一次，核对历史记录显示“普通”，提示词版本保持原版本。
3. 只选「接口测试」，用明确描述接口约定的需求生成。核对合法输入、请求/响应契约和适用的参数边界；未给出的路径、字段、状态码和阈值应标待澄清，不应被虚构。
4. 只选「安全与权限」，用包含角色或资源归属规则的需求生成。核对认证、授权、资源边界和拒绝后的数据状态；未定义角色或权限矩阵时仍需待澄清。
5. 同时开启两个专项，再与普通生成比较。完整策略仍为 3–8 条、包含正常/边界/异常；不会额外追加另一批草稿。
6. 使用冒烟策略验证：仍只生成 1–3 条核心正常路径，专项不应把越权或异常场景塞入冒烟。
7. 在「专项 Skill 与覆盖声明」查看每条 AI 原稿声明的专项，再展开规则快照，核对版本、handler 版本与内容摘要。已启用不代表每条都覆盖，模型可以声明空覆盖。
8. 开启 RAG，再启用一个或两个专项。核对知识引用与专项声明分别展示，不混淆 K 编号与专项 ID。
9. 运行期间暂停、刷新、恢复，确认复用检查点和相同专项快照；历史记录与任务列表均能看到所选专项。

专项复用当前生成配置，不新增 Key，不额外调用另一遍生成模型。Prompt 长度会增加，实际 token 和费用可能变化。RAG 检索、Embedding 与 Rerank 的调用规则保持模块 16 的行为。

## 两个专项的边界

| 专项 | 完整策略关注点 | 冒烟策略关注点 |
| --- | --- | --- |
| 接口测试 | 已声明的请求/响应契约、参数类型和边界、缺失/非法参数；有明确约定时再检查幂等、分页和并发 | 合法输入下的核心成功路径 |
| 安全与权限 | 已声明的认证与会话、角色/资源归属边界、拒绝后数据不变性、敏感字段保护 | 有权限身份的核心正常路径 |

专项只提供设计关注点，不提供新业务事实。当前功能没有接口或权限约定时，模型应保留“待澄清”，而不是为了凑覆盖编造管理员、错误码、锁定次数或接口地址。

本模块设计测试草稿，不执行接口或安全测试；测试执行管理按后续模块继续实现。

## 注册表、Prompt 与 handler

```text
GET /api/skills
    ↓ 选择 [] / [api] / [security] / [api, security]
提交生成任务：校验 ID、保存专项版本快照
    ↓
prepare：注册表分派独立 handler → 结构化关注点 + 专项 Prompt
    ↓
generate：与原生成共用一次调用，可同时接入 RAG
    ↓
validate：原策略检查 + 专项标识检查 + 可选知识引用检查
    ↓
保存草稿、专项声明与原始版本快照
```

- `specialists/registry.py` 显式注册固定 ID、名称、描述、关注点、Prompt 版本与 handler 版本。
- `specialists/prompts/api.md`、`security.md` 分别保存独立专项规则。
- `specialists/handlers.py` 分别组装本功能、本策略的结构化设计关注点；handler 不调用模型、不发网络请求、不执行用户代码。
- 内容摘要同时覆盖专项元信息、Prompt 与 handler 实现。工作流版本也包含注册表摘要，防止恢复时混用规则。

更新规则时应同步更新专项版本并重启服务；Markdown Prompt 不保证被开发服务器自动热加载。当前 handler 实现位于同一文件，修改它可能影响两个专项的摘要，按保守版本保护处理。

## 数据与接口

生成请求新增 `skill_ids`，默认为空数组：

```json
{
  "skill_ids": ["api", "security"]
}
```

其余请求字段保持原样。只接受两个固定 ID；未知 ID、重复项、错误类型和超过两项均返回 422，不能通过参数传入任意 Prompt 或 handler。ID 在后端规范化排序，因此 `[security, api]` 与 `[api, security]` 使用相同请求指纹，可以安全核实同一次提交。

`GET /api/skills` 返回公开目录、版本和内容摘要，不返回 API Key，也不触发模型调用。目录查询失败时，页面允许普通生成并提供重试，不会默默丢掉已选专项。

新增 `generation_skills` 表，关联请求 ID 与需求，保存：

- 请求指纹，避免失败后把同一标识改绑为另一专项或普通生成。
- 选中的名称、版本、handler 版本、关注点、完整 Prompt 与内容摘要。
- 草稿 ID 到模型声明的 `skill_refs` 的映射。

后台任务在提交事务中先保存专项快照；同步生成入口也在模型调用前保存。草稿与专项映射在同一最终事务写入。删除需求或项目会级联清理相关快照，不修改已有草稿字段结构。

生成详情新增 `skills`，没有启用或为旧记录时为 null。历史摘要新增 `skill_names`，任务详情新增 `skill_ids`。提示词版本按组合记录：

| 开关组合 | Prompt 版本 |
| --- | --- |
| 普通生成 | `case-writer-v1` |
| 仅 RAG | `case-writer-rag-v2` |
| 专项，无 RAG | `case-writer-skills-v3` |
| 专项 + RAG | `case-writer-rag-skills-v3` |

不选择专项时，从请求指纹中排除空的新增字段，保留旧成功请求的重放兼容性。

## 覆盖声明不是质量判定

开启专项后，模型可以在每条原稿中返回 `skill_refs` 字符串数组，例如 `["api"]` 或 `["api", "security"]`。后端检查：

- 只能声明本次启用的专项，未知或未启用的 ID 不接受。
- 同一条用例不能重复声明相同 ID。
- 允许空数组，不替模型伪造“已覆盖”。
- 验证失败时整批草稿不入库，不静默删掉标识后当作正常结果。

专项 ID 不改变 `case_type`，用例仍为 functional、boundary、exception。接口和安全专项不会绕过完整/冒烟约束。

声明只对应 AI 原稿。它证明标识属于启用范围，不能证明规则已被正确执行或覆盖充分；人工编辑后需重新核对。页面展示原始规则快照和声明，下一模块再用 Judge 补充质量判断。现有评审、采纳和导出字段保持原格式，专项信息可从来源生成记录追溯。

## 暂停、恢复与升级

节点仍是 `prepare → generate → validate`，没有额外模型节点。准备阶段将所选规则与 handler 关注点加入消息，检查点保存相同快照；暂停恢复复用已有模型结果。

专项版本变化后，不允许用新规则恢复旧任务，历史成功结果仍按原快照展示。模块升级改变了工作流版本，旧版未完成任务需要重新发起；不伪造旧检查点。无新增 Python/npm 依赖，后端启动自动创建新表。

## 学习顺序

1. `backend/app/specialists/registry.py`：固定目录、版本、内容摘要与分派。
2. `backend/app/specialists/handlers.py` 及 `prompts/`：独立行为与规则。
3. `backend/app/skill_snapshots.py`：提交绑定、版本保护与快照复制。
4. `backend/app/workflows/case_generation.py`：上下文拼装、一次生成、声明校验。
5. `backend/app/case_generations.py`、`generation_tasks.py`：事务、恢复与历史证据。
6. `web/src/pages/CaseGeneration.vue`、`components/SkillEvidence.vue`：选择、覆盖声明和规则快照。
7. `backend/tests/test_skills.py`：目录、独立/组合专项、RAG 联动、幂等和恢复验证。

## 验证结果

版本 0.17.0。2026-10-27：196 项后端测试通过（180 项回归 + 16 项专项测试），前端类型检查与构建通过。

浏览器使用临时数据库和模拟生成服务验证组合选择、任务显示、暂停/刷新/恢复、规则快照展开和历史专项列。暂停前后生成调用次数均为 1；未使用用户真实 Key 或额度。真实专项内容质量由本模块验收确认。
