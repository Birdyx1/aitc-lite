# 模块 21：测试任务与人工执行管理

执行闭环：已采纳用例 → 创建人工执行任务 → 保存用例快照 → 人工操作并记录结果 → 结束任务。入口在项目列表「测试执行」，也可从项目「已采纳用例」页进入。

本模块不调用模型、MCP 或自动化脚本；通过、失败、阻塞都是用户填写的人工记录。Agent 可只读查询执行统计，不能改写这些记录。

## 最小功能

- 项目内任务列表、分页、创建与详情。
- 选择 1–200 条已采纳用例，支持关键词/冒烟筛选和勾选。筛选变化保留已选条目，页面显示已选数；「选中当前筛选」最多保留 200 条。
- 创建时填写任务名、环境/版本，执行人和备注可选；保存当时的人工用例版本与来源快照。
- 每条记录未执行、通过、失败或阻塞，填写实际结果/阻塞原因和缺陷备注。
- 修改记录递增版本，保留旧结果历史；相同请求重复提交不重复记账，过期页面不覆盖新结果。
- 所有条目已记录后可结束任务。结束表示本轮记录完成，可包含失败和阻塞；结束后锁定结果。
- Agent 项目概况返回人工执行任务数量、条目统计与最近 5 个任务摘要。

## 手工验收

1. 在草稿页采纳几条用例。如需学习快照，先人工编辑一条再采纳。
2. 项目列表 → 测试执行 → 创建执行任务，填写例如「登录回归」「测试环境 v1.0 / Chrome」。选择用例后「保存快照并创建任务」。
3. 核对任务详情标题、步骤和预期是否与采纳版本一致；Mock 用例来源、人工版本号和创建时依据过期标记应保留。
4. 为一条记录通过、一条失败、一条阻塞。已执行状态均需填实际结果，阻塞写原因；缺陷编号/地址仅作文本保存，不会向外部系统提交。
5. 统计应为已记录 3/3、通过 1、失败 1、阻塞 1，通过率 50%，分母 2。只有未执行或阻塞时，通过率显示「—」，不会补成 0% 或 100%。
6. 修改某条结果，打开「结果历史」，核对旧版本仍在。保存为未执行会清空当前结果/缺陷备注，历史保留。
7. 还有未执行条目时不能结束任务；全部记录后点击「结束任务」，确认当前数量，再核对结束后没有「记录结果」按钮。刷新后结果与状态应一致。
8. 在项目助手询问「查询人工执行统计」，展开项目概况工具，核对 recording_mode=manual、任务数量与分母。真实 Agent 仍可能调用生成模型并计费，显式 Mock 可验证本地只读流程。
9. 新任务可以再次选择同一用例，环境版本可以不同；两个任务分别保存和计数，不共用执行结果。

任务中显示的是创建时快照，不实时替换为最新需求。若来源后来修改或删除，已有任务仍能读取和记录，创建时依据标记也不会被重写。删除整个项目会同时清理执行任务、条目和结果历史，项目删除确认已明确提示。

## 数据与统计规则

### 创建快照

后端在同一写事务内重新核对项目、采纳状态与生成依据。未采纳、其他项目、已删除、重复 ID 或超过数量上限均不创建部分任务。

有生成依据已变化的用例时，默认拒绝；用户在创建页勾选「已人工核对依据过期用例的适用性」后可继续，条目保存 `outdated_at_creation=true`。该确认不等于新生成或重新评审，也不证明当前需求覆盖完整。

快照包含用例全部字段、原用例/生成/需求 ID、原需求标题、模块/功能、生成来源、人工编辑状态与采纳版本号。来源 ID 是追溯文字标识，不设源用例外键，因此源需求级联删除不会清理任务快照。任务仍按项目外键级联。

任务名 1–100 字符，环境/版本 1–500，执行人最多 80，备注最多 2000。名称与环境不能为空白；不接受 NUL 或非法 Unicode。任务基本信息和用例范围创建后固定，本轮不提供编辑、追加条目、复制、删除或重开任务功能；需要新一轮时创建新任务。

### 记录与结束

条目状态：`not_run`（未执行）、`passed`（通过）、`failed`（失败）、`blocked`（阻塞）。通过/失败/阻塞必须有非空实际结果，最多 5000 字符；缺陷备注最多 2000。未执行状态要求当前结果和缺陷备注为空。

每次实际修改递增条目版本及任务版本，追加一条不可编辑的结果事件。相同请求 ID 与相同内容重放返回当前条目，不重复创建事件，也不会把后来修改倒退回旧版本。相同 ID 换条目或换内容返回冲突。

记录结果校验条目版本，结束任务校验任务版本；两者都在短写事务中完成。多页面同时改同一条目只允许一个版本成功，另一页保留输入并提示刷新。任务列表/详情不会自动覆盖正在编辑的表单，按「重新加载任务」核对最新数据。

结束前必须没有未执行条目；有失败或阻塞也可结束，但只表示记录完成。结束后不可新修改，旧成功请求的幂等核对仍可读取。尚未完成的人工任务重启后保持 open、结果保留，不自动变成成功或重新执行。

本模块没有后台自动执行者或远端调用，也没有执行租约接管；版本校验处理同一用户多页面的写入冲突。原用例生成的节点暂停/恢复、Agent/MCP 的确认与重启保护继续独立工作。执行人是用户填写的文字，不是身份认证，本平台仍为本机单人使用。

### 统计口径

- 按任务条目计数；同一用例被多个任务选中时分别统计。
- 已记录 = 通过 + 失败 + 阻塞；未执行另列，不把阻塞说成实际操作已完成。
- 通过率 = 通过 /（通过 + 失败）×100%，保留两位小数；阻塞与未执行排除，分母 0 时为 null，页面显示「—」。
- 任务详情统计本任务全部条目，不随页面关键词/状态筛选改变。
- Agent 项目统计汇总该项目全部历史任务的当前条目状态，同时提供最近 5 个任务摘要。它不是去重后的当前用例质量，也不是自动化运行、需求语义覆盖或 Judge 评分。

Mock 标签标识用例生成来源，执行统计依然来自人工录入；不会因用户记录通过而改写 Mock 来源或原人工采纳结论。

## 阅读顺序与 API

1. `backend/app/models.py`：ExecutionTask、ExecutionItem、ExecutionResultEvent。
2. `backend/app/execution_tasks.py`：创建、快照、项目隔离、结果版本与事件、统计、结束任务。
3. `backend/app/agents/tools.py`：项目概况复用人工执行统计；Prompt 明确统计口径。
4. `web/src/pages/ExecutionTasks.vue`：选择用例、创建表单、列表与分页。
5. `web/src/pages/ExecutionTaskDetail.vue`：按快照人工操作、保存结果、历史、统计和锁定。
6. `backend/tests/test_execution.py`：隔离、快照、幂等、并发、历史与重启验证。

| API | 用途 |
| --- | --- |
| POST `/api/projects/{pid}/execution-tasks` | 稳定 task_id 创建快照 |
| GET 同路径 | 列表，默认每页 20、最多 50 |
| GET `/{task_id}` | 元数据、固定条目快照与当前结果 |
| PUT `/{task_id}/items/{item_id}` | request_id + expected_revision 保存实际结果 |
| GET `/{task_id}/items/{item_id}/history` | 历史结果，版本倒序 |
| POST `/{task_id}/complete` | 当前任务版本校验后结束 |

创建表单或结果表单未保存时，关闭/离开/刷新有提醒。请求结果不明时先刷新列表或历史核对；相同内容在当前编辑器重试沿用原请求标识。环境、缺陷地址等以纯文本展示，不自动打开、请求或执行。
